# Профиль клиента и реферальная ссылка

**Что это.** Два пункта заказчика, доведённые до клиента:

1. у каждого свой «красивый + качественный профиль» в боте — экран **«Мой профиль»**;
2. **реферальная ссылка**, по которой человек приглашает людей через себя и получает
   за это дни.

Плюс третий, связанный: экран **«Локации»** перестал печатать служебные имена
инбаундов и говорит, что действительно работает.

**Где в коде.**

| Что | Файл |
|---|---|
| Экран профиля (хендлер, текст, кнопки) | `app/bot/handlers/profile.py`, `app/bot/texts.py` (`profile_card`), `app/bot/keyboards.py` (`profile_kb`, `BTN_PROFILE`) |
| Цифры профиля | `app/services/profile.py` |
| Реферальная ссылка и экран «Пригласить друга» | `app/bot/handlers/referral.py`, `app/bot/keyboards.py` (`referral_share_kb`) |
| Логика наград | `app/services/referral.py`, скидка — `app/services/promo.py` |
| Экран «Локации» | `app/bot/handlers/subscription.py::cb_locations`, тексты `LOCATIONS_*` |
| Тесты | `tests/test_profile_screen.py`, `tests/test_referral_flow.py` |

## 1. Экран «Мой профиль»

Открывается тремя путями: команда `/profile`, кнопка **«Мой профиль»** в главном меню
(заняла место «Моя подписка» — она и есть личный кабинет) и кнопка в нижней
клавиатуре. В главном меню по-прежнему **не больше шести кнопок и четырёх рядов**
(`tests/test_bot_design.py::test_menu_is_short`).

Как выглядит (пробный доступ, три локации):

```
💎 Мой профиль

Аня @anya
С нами с 08.10.2026 · нас уже 128

📡 Доступ
Статус: пробный
Действует до 11.10.2026 · осталось 3 дн.
██████████ остаток срока: 3 дн.
Локации: Германия — доступна, Нидерланды — не отвечает, Финляндия — нет данных

📱 Подключение
Устройств: до 1
Трафик: 0 ГБ из 10 ГБ

🎁 Приглашения
Приглашено: 2 · оплатили: 1
Заработано: 14 дн. · в запасе: 0 дн.
Осталось наград в этом месяце: 9 из 10
Пригласи друга — скидка 30% ему и +14 дн. тебе.

Цифры обновляются сами: после оплаты, продления и новых друзей.
```

Кнопки: **«Моя подписка»** (зелёная — главное действие экрана), «Пригласить друга»,
«Как подключить», «Помощь». Одно зелёное действие, подписи ≤ 30 символов, без эмодзи.

### Откуда каждая цифра

| Строка | Источник | Что делаем, если данных нет |
|---|---|---|
| Имя, `@username` | `User.display_name`, `User.username` | `display_name` подставляет `id<tg_id>` |
| «С нами с» | `User.created_at` | «—» |
| «нас уже N» | `count(users)` | 0 |
| Статус | `Subscription.status` + `is_active` | нет подписки → «нет доступа» |
| Срок, «осталось N дн.» | `Subscription.expires_at`, `days_left` | далёкая дата (> 10 лет) → «бессрочно» |
| Полоса `█░` | остаток / длительность периода (тариф или срок подписки) | для бессрочной не рисуем; рядом всегда цифра |
| Устройства | `Subscription.devices_limit`, для триала — `TRIAL_DEVICES` | — |
| Трафик | `Subscription.traffic_limit_gb`; расход — `PanelUser.used_bytes` | лимит есть, панель молчит → «до N ГБ» без цифры расхода |
| Тариф | `Plan.title` по `Subscription.plan_id` | пробный доступ → строки нет |
| Последняя оплата | последний `Order` со статусом `paid` | не платил → строки нет |
| Приглашения | `app.services.referral.overview` (invited / paid / earned_days / balance / rewards_left) | нули, но не выдуманные |
| Локации | поля нод + `app.services.probe.probe_verdict` | ни одного замера → «статус появится после первой проверки» |

### Правила честности

* **«Без ограничений» — только при `traffic_limit_gb == 0`.** Если лимит есть, пишем
  «N ГБ из M ГБ»; расход берём из панели, а если панель не ответила — показываем
  только лимит. Ноль в этой строке был бы выдумкой.
* **«Локации доступны» — только по факту пробы.** Пока ни одна нода не проверена,
  строка говорит «статус появится после первой проверки»: система не рапортует о
  состоянии, которого не измеряла (инцидент 08.10.2026).
* **Даты — как есть.** «Бессрочно» показываем вместо «осталось 26 000 дн.»: в базе
  бессрочные хранятся далёкой датой, чтобы фоновые задачи их не погасили.
* **Обещания — из настроек.** Скидка, дни за друга и лимит наград приходят из
  `settings`, а не вписаны в текст руками (`test_profile_card_promises_match_settings`).
* **Никаких внутренних данных.** Ни кодов нод, ни адресов, ни портов, ни имени
  панели — только страна, канал и состояние.

### Если подписки нет

Экран всё равно есть: статус «нет доступа», оффер пробного доступа с реальными
лимитами (`TRIAL_DAYS`, `TRIAL_DEVICES`, `TRIAL_GB`) и понятное «что дальше» —
кнопка «Попробовать бесплатно». Блок приглашений показывается всегда: если человек
уже заработал дни, они видны в строке «в запасе».

## 2. Реферальная ссылка: сквозной сценарий

Ссылка: `https://t.me/<bot_username>?start=ref_<referral_code>`.

### Шаги

1. **Пригласивший открывает «Пригласить друга».** Бот берёт свой `username` через
   `get_me()`, собирает ссылку, показывает её как `<code>` — тап копирует целиком.
   Рядом — готовое сообщение другу и кнопка **«Поделиться с другом»**:
   `https://t.me/share/url?url=<ссылка>&text=<текст>`. Это обычный https-адрес,
   права бота не нужны; Telegram открывает выбор чата и подставляет черновик.
2. **Друг переходит по ссылке и жмёт «Старт».** `app/bot/handlers/start.py` видит
   payload `ref_<код>` и зовёт `referral.attach_referrer`.
3. **Привязка.** Происходит **ровно один раз**: если `User.referred_by` уже стоит —
   выходим сразу. Свою ссылку использовать нельзя (`referrer.id == user.id`),
   заблокированный пригласивший не привязывается. Пишется строка `Referral`, и
   в тот же момент создаётся промокод пригласившего.
4. **Приветствие другу со скидкой.** Показываем **до** гейта подписки на канал:
   иначе друг не увидит обещанную скидку, а пригласивший потеряет награду —
   повторный `/start` уже не отдаст пригласившего.
5. **Друг выбирает тариф.** Скидка считается сама: `promo.available` видит
   `referred_by` и применяет промокод пригласившего на **первую** оплату
   (только на неё — вторая оплата идёт по полной цене).
6. **Друг оплачивает.** `orders.mark_paid` → `referral.reward_on_payment`:
   * пригласившему — `REFERRAL_BONUS_DAYS_REFERRER` дней (по умолчанию 14);
   * другу — `REFERRAL_BONUS_DAYS_INVITED` дней (3) сверху;
   * если у пригласившего нет подписки — дни не сгорают, а копятся в
     `User.bonus_days_balance` и добавляются к сроку при первой оплате.
7. **Повторная награда за того же человека невозможна:** в строке `Referral`
   фиксируется `paid_order_id`, и вторая обработка той же оплаты ничего не начислит.
   За **продления** друга начисляются отдельные дни (`REFERRAL_BONUS_DAYS_RENEWAL`).
8. **Месячный лимит.** Не больше `REFERRAL_MAX_REWARDS_PER_MONTH` наград в
   календарный месяц; после лимита оплата всё равно разбирается и помечается, но
   дни не начисляются, а пригласившему уходит честное уведомление.
9. **Что видит человек.** На экране «Пригласить друга»: ссылка, промокод,
   «Перешли по ссылке / Из них оплатили / Заработано дней», строка про дни за
   продления, лимит наград и готовое сообщение другу. В профиле — те же счётчики
   и «в запасе».

### Что проверено тестами

`tests/test_referral_flow.py` прогоняет сценарий через диспетчер (как живой бот):

* ссылка ведёт на правильного бота и содержит код человека;
* кнопка «Поделиться» отдаёт ссылку и готовый текст;
* «новый человек по ссылке → оплатил → пригласивший получил дни» (в срок подписки);
* у пригласившего без подписки дни уходят в баланс;
* повторный `/start` по той же ссылке не начисляет второй раз;
* свою ссылку использовать нельзя, заблокированный пригласивший не привязывается,
  битый код не ломает `/start`;
* гейт подписки на канал не съедает привязку и скидку.

## 3. Экран «Локации»

Было: список инбаундов панели — «NL-Reality-firefox-u42 — vless, порт 443». Клиенту
это не говорит ничего, а внутренние имена и порты наружу отдавать незачем.
Панели ещё и опрашивались на каждый тап: не ответила — экран пустой.

Стало: страна (название ноды), канал (обычная / резерв / CDN) и вердикт последней
пробы «глазами клиента» (`app.services.probe.probe_verdict`):

| Вердикт | Что пишем |
|---|---|
| `PROBE_OK` | «отвечает, 42 мс» (замер с сервера; без цифры — просто «отвечает») |
| `PROBE_PORT_FAILED` | «порт не пускает» |
| `PROBE_NOT_CONFIGURED` | «проба не настроена» |
| `PROBE_UNKNOWN` | «нет данных пробы» |
| `PROBE_UNAVAILABLE` | «проба не состоялась» |

Данные берутся из таблицы нод, панели не опрашиваются вовсе: экран больше не зависит
от того, отвечает ли чужая панель, и не падает из-за ноды без адреса панели. Нет
замеров — так и написано; пусто — честное «пока нечего показать».

Задержка подписана как замер с сервера: это задержка от нашего сервиса до локации,
а не пинг телефона (его считает приложение клиента).

## 4. Чего мы не делаем (осознанно)

* **Выплат рефереру деньгами нет** — только дни подписки. Деньги требуют статуса
  платёжного агента, отчётности и ручной сверки; дни закрывают ту же мотивацию и
  не создают обязательств перед третьими лицами.
* **Публичного списка адресов нод нет** — ни в боте, ни в документах. Клиент видит
  страну и состояние, адреса живут только в подписке.
* **Расхода трафика нет, если панель молчит** — вместо нуля показываем лимит.
* **Проба по основной панели из `.env` не ведётся** (пробы хранятся у нод), поэтому
  в строке локаций такая панель не появляется: показывать её как «доступна» было бы
  выдумкой. Когда у панели появится строка ноды — появится и замер.
* **Автоначисления денег за приглашения нет** — награда только днями и только после
  реальной оплаты друга.
