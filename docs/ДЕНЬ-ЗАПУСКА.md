# День запуска: от покупки сервера до первой продажи

Этот файл — план на один вечер. Всё, что можно было подготовить заранее, уже готово:
код, тесты, скрипты установки, админка, оплата звёздами, тексты постов.

**Что уже готово (проверено):**

| Готово | Проверка |
|---|---|
| Бот, подписки, продления, рефералка | 131 тест зелёный |
| Оплата: звёзды (включена), СБП, крипта | живой счёт в Stars создаётся |
| Админка в боте и веб-панель `/admin` | работает локально |
| Скрипты: панель, инбаунды, бэкап, healthcheck, preflight | синтаксис ок, логика прогнана на заглушке |
| Инструкция запуска | [ЗАПУСК.md](ЗАПУСК.md) |
| План продаж и контент | [ПРОДАЖИ.md](ПРОДАЖИ.md) |

**Осталось купить только сервер.**

## Шаг 0. Что купить (5 минут)

| Вариант | Цена | Комментарий |
|---|---|---|
| **VDSina, Амстердам** | 600 ₽/мес (1 ядро / 2 ГБ / 50 ГБ / 32 ТБ) | рекомендую: активация за 60 секунд, смена тарифа на ходу, API |
| VDSina, Амстердам | 150 ₽/мес (1 ГБ / 1 ТБ трафика) | хватит на первых 10–15 клиентов, потом тариф меняется |
| xorek.cloud, Германия | ~250 ₽/мес | твой текущий сервер: ждём починки от поддержки, тикет #77313 |

При заказе выбрать **чистую Ubuntu 24.04** (не «Easy WireGuard» и не панели — нам нужен
свой стек). Пароль root придёт в панель хостера.

## Шаг 1. Первый вход (5 минут)

```bash
ssh root@IP                     # пароль из панели хостера

# ключ вместо пароля (2 минуты, сильно безопаснее)
ssh-copy-id root@IP             # выполнить НА СВОЁМ компьютере, не на сервере
```

Проверить время — оно критично для TLS и Reality:

```bash
timedatectl
```

## Шаг 2. Панель 3x-ui (5 минут)

```bash
apt-get update && apt-get install -y git
cd /root && git clone <адрес-репозитория> kometa && cd kometa   # или скопировать папку проекта
bash scripts/install_panel.sh
```

Скрипт сам: обновит систему, поставит панель, настроит firewall (не отрежет тебя от SSH),
и покажет, что дальше. **Сохрани вывод**: там логин, пароль и порт панели,
а также команда получения API-токена.

Получить токен для бота (скоуп `admin` обязателен):

```bash
/usr/local/x-ui/x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin
```

## Шаг 3. Инбаунды: Reality + AmneziaWG (5 минут)

```bash
sudo bash scripts/install_node.sh
```

Скрипт создаст VLESS+Reality (443/tcp) и AmneziaWG (51820/udp), подберёт рабочий домен
маскировки и напечатает **ID инбаундов** — они нужны в `.env`.

Проверка, что порты слушаются:

```bash
ss -tulpn | grep -E ':(443|51820)\b'
```

## Шаг 4. Заполнить `.env` (5 минут)

| Переменная | Что вписать |
|---|---|
| `BOT_TOKEN` | уже заполнен |
| `ADMIN_IDS` | уже заполнен |
| `PANEL_TYPE` | `xui` (сейчас `fake` — режим разработки) |
| `PANEL_URL` | `http://IP:ПОРТ_ПАНЕЛИ` (порт напечатал `install_panel.sh`) |
| `PANEL_TOKEN` | токен из шага 2 |
| `PANEL_INBOUND_IDS` | ID из шага 3, через запятую: `1,2` |
| `PANEL_SUB_BASE` | `http://IP:2096/sub/` — сервис подписок панели |
| `PUBLIC_BASE_URL` | `http://IP:8090` — по этому адресу клиенты получают конфиги |
| `MANUAL_PAYMENT_DETAILS` | реквизиты взрослого (СБП/карта) — без них способ оплаты скрыт |
| `ADMIN_PANEL_PASSWORD` | уже сгенерирован, лежит в `.env` |

## Шаг 4.5. Автоподтверждение переводов (по желанию, но экономит часы)

Без него каждый перевод по СБП придётся подтверждать руками. С ним система сама находит платёж
и выдаёт подписку: заказ получает **уникальную сумму** (199.13 ₽) и код в комментарии
(«Kometa 42»), а автоплатёж сопоставляет поступления из выписки.

**Вариант А — почта банка (проще).** Включи в банковском приложении уведомления о поступлениях
на email и заполни в `.env`:

```bash
BANK_IMAP_HOST=imap.yandex.ru      # или imap.gmail.com, imap.mail.ru
BANK_IMAP_PORT=993
BANK_IMAP_USER=you@yandex.ru
BANK_IMAP_PASSWORD=<пароль приложения, НЕ обычный пароль от почты>
AUTOPAY_ENABLED=true
```

**Вариант Б — файл выписки.** Скачивай CSV из банка (или выгружай скриптом) в папку:

```bash
STATEMENT_CSV_GLOB=data/statements/*.csv
AUTOPAY_ENABLED=true
```

**Проверка без ожидания планировщика:**

```bash
.venv/bin/python -m app.tools.autopay --dry-run   # только показать, что видит система
.venv/bin/python -m app.tools.autopay             # подтвердить по-настоящему
```

⚠️ Не запускай на реальных деньгах, пока `--dry-run` не покажет, что твой тестовый перевод
находится и сопоставляется с заказом. Несопоставленные поступления никогда не теряются —
о них бот пишет админу.

Крипта и звёзды работают автоматически без этой настройки.

## Шаг 4.6. WATA: оплата картой и СБП (главный способ для роста)

WATA — платёжная система, у которой **VPN это отдельное направление**: принимает карты МИР/Visa/Mastercard,
СБП, T-Pay, SberPay и отдаёт готовую страницу оплаты. Интеграция в коде уже готова, включается токеном.

**Порядок подключения (делает взрослый, на кого оформлен приём денег):**

> ⚠️ **Главное про деньги:** в заявке WATA есть выбор — **оплатить сбор 50 000 ₽ / $500** либо прийти
> **по рекомендации** того, кто уже подключён. Это в 5 раз больше стартового бюджета, поэтому:
> сейчас продаём через Stars и переводы, а WATA подключаем, когда оборот станет стабильным
> (сбор окупается за 1–3 месяца при выручке ≥ 50 тыс. ₽/мес). Заявку подать стоит уже сейчас —
> и спросить менеджера про вариант без сбора.

**Что спросить у менеджера WATA** (готовым сообщением):

> Здравствуйте! Запускаем VPN-сервис по подписке в Telegram, интеграция с вашим API уже готова.
> Стартовый оборот — 30–100 тыс. ₽/мес, средний чек 250 ₽. Подскажите:
> 1) возможен ли старт без сбора за подключение или с рассрочкой;
> 2) зачитывается ли сбор в будущий оборот;
> 3) какие условия по рекомендации от действующего мерчанта;
> 4) какие лимиты и сроки выплат на старте.

1. Заявка на <https://wata.pro/vpnforbusiness> (или письмо на connect@wata.pro) — нужен ИП/ООО.
2. Менеджер присылает доступ в кабинет <https://merchant.wata.pro/login>, создаёшь терминал.
3. В разделе **«Терминалы»** → создать **access token** (срок жизни 1–12 месяцев). Токен показывается
   один раз — сохрани.
4. **Сообщи менеджеру IP сервера** — WATA принимает запросы только с согласованных адресов.
5. В кабинете укажи URL вебхука: `https://<IP или домен>:<WEB_PORT>/payments/wata/webhook`
6. Впиши в `.env`:

```bash
WATA_TOKEN=<токен терминала>
WATA_BASE_URL=https://api.wata.pro/api/h2h
# для тестов: WATA_BASE_URL=https://api-sandbox.wata.pro/api/h2h
```

7. Проверка: `bash scripts/preflight.sh` — должно быть «WATA: токен принят, публичный ключ получен».

**Проверка на тестовых картах (песочница):**

| Тип | Карта | Результат |
|---|---|---|
| МИР без 3DS | `2200 0000 2222 2222` | успех |
| МИР без 3DS | `2203 0000 0000 0043` | отказ |
| МИР с 3DS | `2200 0000 0000 0004` | успех |
| Visa с 3DS | `4242 4242 4242 4242` | успех |
| Visa без 3DS | `4000 0000 0000 3055` | успех |

Купи свой тариф тестовой картой — подписка должна включиться сама за пару секунд (вебхук),
а в админке появиться заказ со статусом «оплачен».

> Если WATA ещё не одобрили — не жди: Stars и переводы с автоплатежом работают уже сейчас.

## Шаг 5. Проверка до запуска (2 минуты)

```bash
bash scripts/preflight.sh
```

Скрипт скажет прямым текстом, что не так: токен бота, панель, инбаунды, реквизиты,
публичный адрес. **Пока он не покажет «Всё готово» — продажи не открываем.**

## Шаг 6. Запуск (3 минуты)

```bash
curl -fsSL https://get.docker.com | sh
docker compose up -d
docker compose logs -f bot          # ждём «Бот запущен: @...», «Способы оплаты: ...»
```

Проверка:
* бот отвечает на `/start`;
* `/admin` в боте показывает статистику;
* `http://127.0.0.1:8090/admin` через SSH-туннель — веб-панель.

```bash
ssh -L 8090:127.0.0.1:8090 root@IP   # на своём компьютере, потом открыть панель локально
```

## Шаг 7. Тест на себе — обязательно (15 минут)

1. В боте: «Попробовать бесплатно» → получить ссылку-подписку.
2. **Подключиться с телефона по-настоящему**: поставить v2rayNG/Hiddify, вставить ссылку,
   обновить подписку, включить.
3. Проверить: открывается YouTube/Instagram, скорость нормальная.
4. Переключить локацию — убедиться, что подписка общая для всех инбаундов.
5. Купить тариф **звёздами** (это реальные деньги, минимальный пакет) → проверить,
   что доступ включился сам и пришло подтверждение со ссылкой.
6. Создать заказ с оплатой по СБП → подтвердить его в админке → убедиться, что
   пользователю ушло сообщение.

Только после этого шага можно звать людей.

## Шаг 9. Первая неделя — что смотреть

| Метрика | Где | Цель |
|---|---|---|
| Пробные доступы | `/stats` в боте | 10+ |
| Конверсия в оплату | `/admin` → дашборд | ≥ 20 % |
| Выручка | `/admin` → дашборд | первые 1 000 ₽ |
| Обращения | поддержка | ≤ 1 на 5 клиентов |
| Ноды | `/admin` → ноды, `healthcheck.sh` | всегда отвечают |

Включить автоматику на сервере:

```bash
crontab -e
# бэкап каждый день в 4:30
30 4 * * * cd /root/kometa && bash scripts/backup.sh >/dev/null 2>&1
# проверка здоровья каждые 15 минут с уведомлением в Telegram
*/15 * * * * cd /root/kometa && bash scripts/healthcheck.sh --notify --quiet
```

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Preflight: «Панель не ответила» | проверь `PANEL_URL`/`PANEL_TOKEN`, `systemctl status x-ui`, порт в firewall |
| Preflight: «нет инбаундов с ID» | перезапусти `install_node.sh`, посмотри ID в панели и поправь `PANEL_INBOUND_IDS` |
| Бот молчит | `docker compose logs bot`, проверь `BOT_TOKEN` |
| Ссылка не открывается на телефоне | `PUBLIC_BASE_URL` должен быть с внешним IP, порт 8090 открыт в firewall |
| Клиент подключился, но интернета нет | проверь Reality-инбаунд: домен маскировки, порт 443, `ss -tulpn` |
| Оплата звёздами не проходит | бот должен отвечать на `pre_checkout_query` (уже реализовано), проверь логи |
| Хочется откатиться | предыдущий образ + дамп БД: раздел «Восстановление» в [ЗАПУСК.md](ЗАПУСК.md) |

## Правила, которые нельзя нарушать

1. **Никакой рекламы с формулировками про «обход»** — штраф 50–80 тыс. ₽. Только «защищённое подключение».
2. **Реквизиты — взрослого человека** (родитель или друг 18+), у него же налог 6 %.
3. **Не выставлять админку в открытый интернет по HTTP** — только SSH-туннель или HTTPS.
4. **Бэкапы каждый день** — иначе одна авария уносит всех клиентов.
