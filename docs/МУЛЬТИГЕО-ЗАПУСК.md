# Мультигео: как добавить страну

> ⚠️ Внутренний документ: не для публикации. Здесь адреса серверов, токены и служебные
> команды. В публичные тексты (бот, канал, `docs/legal/`) попадает только фраза
> `LOCATIONS_NOTE` из `.env` — её проверяет `tests/test_public_texts_clean.py`.

**Схема (реализовано 06.10.2026): у каждой страны — своя панель 3x-ui, бот работает
с ними со всеми.** Клиент создаётся на каждой панели с одним и тем же uuid и email,
поэтому ссылка-подписка отдаёт конфиги всех стран, а продление, блокировка и истечение
применяются сразу везде.

```
   Telegram-бот
        │
        ├──► панель 1: 🇩🇪 Германия (VPS №0 — там же бот)      ← PANEL_* из .env
        └──► панель 2: 🇯🇵 Япония   (свой VPS)                 ← нода из админки

   одна ссылка-подписка ──► в приложении две локации, переключение тапом
```

Мастер-панель и `node-sync` **не нужны**: не требуется обновлять 3x-ui до 3.7+ и
рисковать живой панелью. Нода подключается формой в админке (раздел «Ноды и панель»).

Что получает клиент: та же одна ссылка-подписка, но в приложении — список стран.
Clash/Mihomo и sing-box сами выбирают быструю локацию, v2rayNG/Happ/Hiddify
переключают страну тапом.

Стоимость и когда переходить — [РЕМНАВАВЕ-СВЯЗКА.md](РЕМНАВАВЕ-СВЯЗКА.md).
Какие страны брать первыми — [ГЕОГРАФИЯ-И-ПИНГ.md](ГЕОГРАФИЯ-И-ПИНГ.md).

## 2. Основная панель (делается один раз)

На VPS №0 — там же, где живёт бот:

```bash
cd /root/kometa
sudo bash scripts/install_panel.sh          # панель + firewall + логин/пароль
sudo bash scripts/install_node.sh           # инбаунды основной панели (она же локация №1)
```

Токен для бота (скоуп **admin**, не `node-sync`):

```bash
/usr/local/x-ui/x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin
```

Токен показывается один раз — сохрани. Он идёт в `.env` как `PANEL_TOKEN`.

Если основной сервер **не** должен быть локацией (правильнее для устойчивости: панель
и локация на разных машинах), шаг `install_node.sh` пропускается, а первая страна
добавляется как нода по разделу 3.

### 2.1. Переезд с локального `PANEL_TYPE=fake` на один сервер

Частый старт: основная панель, локация №1 и бот — на одной машине.

1. **Локальный запуск бота надо остановить.** Пока на компьютере работает
   `python -m app.main`, серверный экземпляр с тем же токеном будет конфликтовать за опрос
   Telegram (`Conflict: terminated by other getUpdates request`) — бот станет отвечать
   нестабильно. Одновременно работает ровно один экземпляр.
2. **Локальную базу переносить не нужно** — стартуем с чистой. В локальной `data/kometa.db`
   лежит подписка, выданная заглушкой `fake`: её `panel_user_uuid` в реальной панели
   не существует, и ссылка такого клиента вернёт `503 no configs available`.
   На сервере `data/kometa.db` создастся сам, тарифы засеются при первом запуске.
3. **`PUBLIC_BASE_URL` = `http://IP_МАСТЕРА:<WEB_PORT>`** (у нас `8090`). Пока там
   `127.0.0.1`, клиенты получат нерабочую ссылку-подписку.
4. **`SALES_ENABLED=true`** — только после проверки раздела 5. Лучше: выдать себе
   пробный доступ и подключиться с телефона.

Готовность проверяется скриптом (он же скажет, что ещё не настроено):

```bash
bash scripts/preflight.sh
```

## 3. Новая страна (повторять для каждой)

### 3.1. Поставить панель на новом сервере

```bash
# Ubuntu 24.04, root
cd /root/kometa                            # проект скопирован на ноду (git clone / rsync)
sudo bash scripts/install_panel.sh         # панель 3x-ui + Xray
```

Дальше — как на немецком узле (раздел 2.2): создать в панели два инбаунда:

| Инбаунд | Протокол | Порт | Имя (remark) |
|---|---|---|---|
| Основной | VLESS + Reality | 443/tcp | `JP-REALITY` |
| Резервный | AmneziaWG | 990/udp | `JP-AWG` |

Записать **ID инбаундов** (колонка ID в списке Inbounds) и выпустить токен API:

```bash
x-ui setting -getApiToken
```

Не забыть про firewall: `ufw allow 443/tcp` и `ufw allow 990/udp`.
Порт панели наружу открывать не нужно — бот ходит к панели по адресу,
который ты укажешь (если панель слушает только localhost, добавь SSH-туннель
или открой порт только для IP основного сервера).

### 3.2. Добавить ноду в админке бота

**Админ-панель → «Ноды и панель» → «Добавить страну»**:

| Поле | Пример | Что это |
|---|---|---|
| код | `jp` | короткий код ноды (латиница, без пробелов) |
| название | `🇯🇵 Япония` | **имя локации в приложении** — его увидит клиент |
| страна | `JP` | двухбуквенный код страны |
| IP | `203.0.113.77` | адрес сервера |
| адрес панели | `http://203.0.113.77:2053/путь` | `PANEL_URL` этой панели |
| API-токен | `...` | вывод `x-ui setting -getApiToken` |
| ID инбаундов | `1,2` | инбаунды, из которых собирается подписка |

После сохранения нода сразу участвует в выдаче: следующий пробный/оплаченный клиент
появится и на ней, а подписка начнёт отдавать её локацию.

### 3.3. Проверить

```bash
# 1) нода видна боту
#    админка → «Ноды и панель»: панель должна быть «отвечает»
# 2) у нового клиента два конфига
curl -s "http://127.0.0.1:8443/sub/<TOKEN>?format=plain" | grep -c '^vless://'   # ожидаем 2
# 3) каждая локация подписана своей страной
curl -s "http://127.0.0.1:8443/sub/<TOKEN>?format=plain" | python3 -c \
  "import sys,urllib.parse;[print(urllib.parse.unquote(l.rsplit('#',1)[-1])) for l in sys.stdin]"
# ожидаем: 🇩🇪 Германия и 🇯🇵 Япония
```

**Важно про уже выданных клиентов.** Новая нода появляется в подписке только у тех,
кто получил доступ **после** её подключения: клиенты создаются на панелях в момент
выдачи. Старым клиентам ключ на новой ноде нужно раздать отдельно — начислить дни
через `/grant` (вызов `extend_days` создаёт клиента, если его нет) или пересоздать
подписку.

## 4. Что поправить в `.env`

| Переменная | Значение | Почему |
|---|---|---|
| `PANEL_TYPE` | `xui` | сейчас стоит `fake` — с ним реальных локаций не будет |
| `PANEL_URL` | `http://IP_ГЕРМАНИИ:2053/<web_base_path>` | это **основная** панель; остальные страны — из админки |
| `PANEL_TOKEN` | токен со скоупом `admin` | создание/продление клиентов |
| `PANEL_INBOUND_IDS` | инбаунды **основной** панели, напр. `1` | у каждой ноды свои ID, они задаются в админке |
| `PANEL_SUB_BASE` | `http://IP_МАСТЕРА:2096/sub/` | из него бот забирает готовые конфиги |
| `LOCATIONS_NOTE` | «Финляндия, Швеция, Нидерланды — переключение в один тап» | попадает на экран покупки и в юр. документы |
| `PUBLIC_BASE_URL` | `http://IP_МАСТЕРА:<WEB_PORT>` (у нас `8090`) или домен | именно этот адрес уходит клиентам в ссылке-подписке; `127.0.0.1` тут оставлять нельзя |
| `SALES_ENABLED` | `true` | включать, **когда хотя бы одна локация реально работает** |

После правки:

```bash
docker compose up -d          # перечитать .env
docker compose logs -f bot
```

## 5. Проверка, что страны появились

```bash
# сколько конфигов отдаёт наша ссылка (должно быть = числу Reality-инбаундов):
curl -s "http://127.0.0.1:<WEB_PORT>/sub/<TOKEN>?format=plain" | grep -c '^vless://'

# видно ли разные адреса (по одному на страну):
curl -s "http://127.0.0.1:<WEB_PORT>/sub/<TOKEN>?format=plain" | grep -o '@[^:]*' | sort -u

# глазами клиента Clash / sing-box:
curl -s "http://127.0.0.1:<WEB_PORT>/sub/<TOKEN>?format=clash"    | head -40
curl -s "http://127.0.0.1:<WEB_PORT>/sub/<TOKEN>?format=singbox"  | head -40
```

> `<WEB_PORT>` — порт веб-слоя из `.env` (у нас **8090**). Локально проверяем через `127.0.0.1`,
> снаружи — через `http://IP:<WEB_PORT>`, там должен открываться тот же ответ.

В боте: «Моя подписка» → «Локации» должно показать все страны; админ-команда `/nodes`
показывает панель и число инбаундов. Обновление подписки подтянет новые локации
без смены ссылки — клиенту переустанавливать приложение не нужно.

## 6. Правила имён локаций

* **Имя локации в приложении = remark инбаунда**, других источников имени нет.
* Формат: `🇫🇮 Финляндия · Reality` / `🇫🇮 Финляндия · AWG`. Флаг + страна, при желании город.
* Имена должны быть **уникальны**: Clash и sing-box не терпят двух прокси с одинаковым
  именем (наш генератор подписок добавляет ` (2)`, но лучше не доводить).
* Пиши по-русски: аудитория русскоязычная, а «Finland» в списке локаций смотрится хуже.
* Меняешь имя — меняй в панели, не в коде.

## 7. Грабли (проверено по коду)

1. **`PANEL_INBOUND_IDS` нужно расширять при каждой новой стране.** Клиент создаётся
   только в перечисленных инбаундах ([app/panels/xui.py:460](../app/panels/xui.py#L460)).
   Забыл добавить ID — в новой стране клиентов не будет вовсе.
2. **Опечатка в ID ломает подписку всем:** при отсутствующем инбаунде панель возвращает
   ошибку `в панели не найдены инбаунды [...]` — ни один клиент не создаётся и не продлевается.
   Что делать: `.venv/bin/python -m app.tools.check_nodes` покажет настроенные ID рядом с
   фактическими и подскажет, что вписать в `/admin/nodes` (код возврата 1). Опечатку в форме
   («3x») админка больше не сохраняет: пустое поле значит «все инбаунды», и молча превращать
   в него ошибку нельзя. Разбор инцидента — [ПЛАН-ПОЧИНКА-НОДА-НЕТ-ИНБАУНДОВ.md](ПЛАН-ПОЧИНКА-НОДА-НЕТ-ИНБАУНДОВ.md).
3. **Панели независимы.** Упала панель ноды — клиенты остальных стран работают, а
   недоступная страна просто не попадёт в подписку до следующей выдачи (бот пишет это
   в лог и в админке раздел «Ноды и панель» показывает «нет ответа»). Обратная сторона:
   ключи на новой ноде получают только те, кому выдали доступ после её подключения.
4. **AmneziaWG не виден в Clash** — ядро Clash не поддерживает wireguard-прокси в подписке.
   Резервные локации доступны в sing-box (`?format=singbox`); в base64-списке AWG-строки есть.
5. **Страница `/status` показывает локации по названию** («🇩🇪 Германия», `LOCATION_TITLE` /
   название ноды): раньше там было служебное `xui` у всех панелей сразу.
6. **Health-check нод** ([job_node_health](../app/main.py), каждые 5 минут) опрашивает все
   панели и пишет админам, если какая-то не отвечает. Проба «глазами клиента»
   ([job_node_probe](../app/main.py), тоже каждые 5 минут) проверяет TCP-порт инбаунда: если
   проба не дошла до порта (панель не отдала инбаунды), алерт `node_probe_failed` не поднимается —
   «порт не пускает клиента» было бы выдумкой, причина видна в строке ноды
   (`nodes.last_probe_error`).
7. **`SALES_ENABLED=true` только когда локация реально отдаёт конфиг.** Проверка — раздел 5.
8. **Проверять ID одной страной бесполезно.** `preflight.sh` и `healthcheck.sh` сверяют
   `PANEL_INBOUND_IDS` (основная панель) и отдельно — ноды из таблицы `nodes` тем же кодом, что
   и бот (`app/tools/check_nodes.py`). Раньше они искали ID грепом по сырому JSON панели, а там
   у элементов `clientStats` своё поле `id`: проверка находила «инбаунд» в статистике клиента и
   рапортовала «всё на месте» при сломанной ноде. Разбор — `docs/ПЛАН-ПОЧИНКА-НОДА-НЕТ-ИНБАУНДОВ.md`.
9. **Адрес сервиса подписок у ноды заполняется в форме.** Пусто — подставится
   `http://<адрес сервера>:2096/sub/`. Если у панели ноды свой порт или путь подписки, впиши его в
   поле «Адрес сервиса подписок»: без адреса бот не заберёт у панели конфиги, и страна молча
   пропадёт из подписки. Форма не даёт включить ноду без адреса — это не придирка, а та самая
   потерянная локация.
10. **Расширил набор инбаундов ноды — досоздай клиентов.** Новые клиенты получат новый порт
   сами, а выданные раньше — нет: `/sync` проверяет наличие клиента на панели, а не в каждом
   инбаунде. Дырку закрывает `.venv/bin/python -m app.tools.sync_inbounds` (dry-run) и
   `--apply` для записи: он доводит состав клиентов до настроек по каждому инбаунду и переносит
   существующий объект клиента (тот же uuid/subId).
11. **Белые списки у оператора — по региону.** Для Дальнего Востока домены маскировки
   подбираются иначе ([scripts/install_node.sh](../scripts/install_node.sh),
   `WHITELIST_SNI_CANDIDATES`), тестируй на месте.

## 8. Чек-лист добавления страны (копипаст)

- [ ] Куплен VPS в нужной стране, Ubuntu 24.04, root-доступ
- [ ] Проект скопирован на сервер, `sudo bash scripts/install_panel.sh`
- [ ] В панели созданы два инбаунда: VLESS+Reality (443) и AmneziaWG (990)
- [ ] `ufw allow 443/tcp` и `ufw allow 990/udp`, панель доступна боту
- [ ] Выпущен токен: `x-ui setting -getApiToken`
- [ ] В админке бота: «Ноды и панель» → «Добавить страну» (код, название, IP, адрес панели, токен, ID инбаундов)
- [ ] В админке панель показывает «отвечает»
