Эта инструкция проведёт от пустого сервера до работающего бота и VPN-ноды.

на сервере по SSH, если рядом не написано «на своём компьютере».

## 1. Что понадобится

| Что | Зачем | Где взять | Сколько |
|---|---|---|---|
| **VPS** (сервер) Ubuntu 24.04, 1 vCPU / 1 ГБ RAM / 10+ ГБ | здесь живут панель, VPN-ноды и бот | любой хостер (Xorek, VDSina, 4VPS…) | 150–450 ₽/мес |
| **Токен бота** | без него бот не подключится к Telegram | @BotFather в Telegram | бесплатно |
| **Твой Telegram ID** | чтобы открылась админка в боте | @userinfobot | бесплатно |
| **Домен** *(не обязательно)* | красивая ссылка на панель и TLS-сертификат | любой регистратор | 200–900 ₽/год |
| **Карта/кошелёк совершеннолетнего** | приём денег (СБП, крипта) | — | — |

**Время:** 20–30 минут, если сервер уже куплен и ты залогинен под root.

Что мы получим в итоге:

```
Telegram ──> бот Kometa (Docker, long polling)
                │  REST API
                ▼
         панель 3x-ui ──> VLESS+Reality (443/tcp)
                └────────> AmneziaWG   (51820/udp)
```

Бот продаёт подписку, создаёт пользователей в панели и отдаёт каждому одну
постоянную ссылку `http://<сервер>:8080/sub/<token>`, которую клиент
(v2rayNG, Hiddify, Happ, sing-box) открывает как «подписку».

## Шаг 1. Создаём бота у @BotFather

1. Открой Telegram и в поиске набери **@BotFather** (у него синяя галочка).
   Осторожно: есть подделки с похожими никами — важен именно `@BotFather`.
2. Нажми **Start**. Бот ответит списком команд и кнопкой **Menu** слева от поля ввода.
3. Отправь команду `/newbot`.
   * BotFather спросит: **«Alright, a new bot. How are we going to call it?
     Please choose a name for your bot.»** — это имя, которое увидят люди.
     Пиши, например: `Kometa — защищённое подключение`. Имя можно с эмодзи и пробелами.
   * Второй вопрос: **«Good. Now let's choose a username for your bot.
     It must end in `bot`.»** — это технический ник, только латиница, цифры и `_`,
     обязательно заканчивается на `bot`. Например: `kometa_vpn_bot`.
     Если занято — BotFather скажет **«Sorry, this username is already taken»**,
     добавь цифры или другое слово.
4. После успеха BotFather пришлёт сообщение **«Done! Congratulations on your new bot.»**
   Внутри — блок с токеном вида:

   ```
   Use this token to access the HTTP API:
   7123456789:AAH3kQwErTyUiOpAsDfGhJkLzXcVbNmQqW
   ```

   Это и есть **BOT_TOKEN**. Скопируй его целиком (две части через двоеточие).
   **Никому не показывай**: кто знает токен — управляет ботом.

5. Пока ты здесь, настрой бота (всё через меню/команды BotFather):
   * `/setdescription` → выбери бота → текст: «Стабильное защищённое подключение.
     3 дня бесплатно. Тарифы от 199 ₽.» (без слов «обход блокировок» — см. ТЗ, раздел 2.3).
   * `/setabouttext` → короткое описание для профиля.
   * `/setuserpic` → аватар (квадратная картинка 512×512).
   * `/setcommands` → выбери бота → вставь список команд (важно для кнопки «Меню»):

     ```
     start - Главное меню
     menu - Показать меню
     id - Узнать свой Telegram ID
     support - Написать в поддержку
     ```

6. Узнай **свой Telegram ID**: напиши **@userinfobot** — он ответит
   `Id: 123456789`. Это число пойдёт в `ADMIN_IDS` (можно несколько через запятую).

7. Если у тебя есть канал — добавь бота в канал **администратором**,
   чтобы он мог проверять подписку. Ссылку на канал (например `https://t.me/kometa_vpn`)
   впиши в `CHANNEL_URL`.

## Шаг 2. Сервер: первый вход

Хостер присылает IP-адрес и пароль root. Заходим (на своём компьютере):

```bash
ssh root@IP_СЕРВЕРА
```

Дальше выполняем на сервере:

```bash
# 1. Обновляем систему
apt-get update && apt-get upgrade -y

# 2. Ставим то, что нужно для работы с проектом
apt-get install -y git curl nano ufw

# 3. Проверяем время — оно критично для VPN и TLS
timedatectl
# Если время не UTC и хочется иначе: timedatectl set-timezone Europe/Moscow
```

### Ключ вместо пароля (сделай сразу, это 2 минуты)

На **своём компьютере** (не на сервере):

```bash
ssh-keygen -t ed25519 -C "kometa"      # если ключа ещё нет — Enter на все вопросы
ssh-copy-id root@IP_СЕРВЕРА            # ввести пароль root последний раз
ssh root@IP_СЕРВЕРА                    # должно пустить без пароля
```

На сервере отключаем вход по паролю:

```bash
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart ssh
```

> ⚠️ Не закрывай текущую сессию, пока не убедился, что новая сессия по ключу
> открывается. Если что-то сломалось — вернёшь пароль через консоль хостера.

## Шаг 4. Устанавливаем панель 3x-ui

Устанавливаем **нативно** (не в Docker) — так её база лежит в `/etc/x-ui/x-ui.db`,
и `scripts/backup.sh` забирает её автоматически.

```bash
cd /root/kometa
sudo bash scripts/install_panel.sh
```

Что делает скрипт (можно перечитать в `scripts/install_panel.sh`):

1. проверяет root, версию ОС, архитектуру и доступ в интернет;
2. обновляет пакеты, ставит `curl`, `openssl`, `ufw`, `certbot`, `jq`, `sqlite3`;
3. ставит 3x-ui **официальным установщиком**
   ([github.com/MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui), скрипт
   `https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh`);
4. открывает в firewall порты: SSH, порт панели, 80/tcp, 443/tcp,
   UDP-порт AmneziaWG (51820) и 8080/tcp под ссылку-подписку;
5. печатает логин/пароль панели, инструкцию по TLS и по получению API-токена.

Полезные флаги:

```bash
sudo bash scripts/install_panel.sh --port 54321 --awg-port 51820   # свои порты
sudo bash scripts/install_panel.sh --reinstall                     # обновить панель
sudo bash scripts/install_panel.sh --no-firewall                   # не трогать ufw
```

**В конце скрипт покажет блок «ПАНЕЛЬ 3x-ui ГОТОВА»** — сохрани оттуда логин, пароль,
порт и web base path. Тот же результат установщик кладёт в `/etc/x-ui/install-result.env`
(права 600, читает только root).

Открыть панель: `http://IP_СЕРВЕРА:54321/<web_base_path>`.
Первый вход — под логином/паролем из вывода скрипта.

### TLS для панели (по желанию, но правильно)

Если есть домен (например `panel.example.com`, A-запись → IP сервера):

```bash
certbot certonly --standalone -d panel.example.com --agree-tos -m you@example.com --non-interactive
/usr/local/x-ui/x-ui setting \
  -webCert /etc/letsencrypt/live/panel.example.com/fullchain.pem \
  -webCertKey /etc/letsencrypt/live/panel.example.com/privkey.pem
systemctl restart x-ui
```

Теперь панель открывается по `https://panel.example.com:54321/<web_base_path>`.
В `.env` тогда пиши `PANEL_URL=https://panel.example.com:54321/<web_base_path>`.

> Сертификат Let's Encrypt живёт 90 дней. Продление: `certbot renew` (можно повесить
> в cron) + `systemctl reload x-ui`.

### Получаем API-токен панели

```bash
/usr/local/x-ui/x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin
```

Вывод:

```
apiToken: 3f9c...длинная_строка...
```

* Токен показывается **один раз** — в базе панели хранится только его хеш.
* Нужен **скоуп `admin`**: боту доступны `inbounds/list`, `clients/add|update|del`
  и чтение трафика; скоуп `node-sync` этих прав не даёт.
* Повторный запуск той же команды **выпускает новый токен и убивает старый** —
  это и есть способ ротации при утечке.
* Через браузер то же самое: **Settings → API Tokens → Create**, Scope: `admin`.

## Шаг 5. Создаём инбаунды: VLESS+Reality и AmneziaWG

Инбаунд — это «вход» на сервере, к которому подключаются клиенты. Делаем два:
Reality (TCP 443) как основной и AmneziaWG (UDP 51820) как резервный.

```bash
cd /root/kometa
sudo bash scripts/install_node.sh
```

Скрипт:

1. берёт `PANEL_URL` и `PANEL_TOKEN` из `.env` (если файла ещё нет — передай флагами
   `--panel-url http://IP:54321/<path> --panel-token <токен>`);
2. генерирует ключи Reality командой `xray x25519` (бинарник из панели) и `shortId`;
3. подбирает домен маскировки (SNI) из списка рабочих и **проверяет его**:
   TLS 1.3 + HTTP/2 + валидный сертификат (`openssl s_client ... -tls1_3 -alpn h2`);
4. создаёт в панели инбаунд **VLESS + Reality** на 443/tcp;
5. создаёт инбаунд **AmneziaWG** на 51820/udp (штатная поддержка 3x-ui с версии 3.7.0 —
   внутри amneziawg-go, никаких kernel-модулей и awg-quick);
6. печатает ID созданных инбаундов, их параметры и команды проверки портов.

Полезные флаги:

```bash
sudo bash scripts/install_node.sh --sni www.microsoft.com     # свой домен маскировки
sudo bash scripts/install_node.sh --dry-run                   # только показать план
sudo bash scripts/install_node.sh --test-client               # + тестовый клиент и ссылка vless://
sudo bash scripts/install_node.sh --no-awg                    # только Reality
sudo bash scripts/install_node.sh --token-only                # режим «нода для мастер-панели»
```

Повторный запуск безопасен: инбаунды ищутся по имени (`Kometa-Reality-443`,
`Kometa-AWG-51820`) и не дублируются.

**Проверь, что порты слушаются** (эту команду печатает и сам скрипт):

```bash
ss -tulpn | grep -E ':(443|51820)\b'
```

Ожидаемый вывод — строки со `LISTEN` для `:443` (xray) и `UNCONN`/`udp` для `:51820`.

Ещё две проверки:

```bash
# домен маскировки действительно годный (должно быть TLSv1.3 и h2):
openssl s_client -connect www.microsoft.com:443 -servername www.microsoft.com \
  -tls1_3 -alpn h2 </dev/null | grep -E 'Protocol|ALPN'

# снаружи, со своего компьютера (TCP-порт должен открываться):
nc -vz IP_СЕРВЕРА 443
```

### Где взять ID инбаундов

* Их печатает `install_node.sh` в блоке «ИТОГИ: ЧТО ВПИСАТЬ В .env».
* Либо в панели: **Inbounds** → колонка **ID** (первая).

Запиши: например `PANEL_INBOUND_IDS=1,2`.

### Если нода отдельная от панели

Схема «мастер-панель + нода»: на ноде ставим панель (`install_panel.sh`),
затем выпускаем токен синхронизации:

```bash
sudo bash scripts/install_node.sh --token-only
```

Скрипт напечатает адрес ноды и `node-sync` токен — вписываешь их в мастер-панели
(**Nodes → Add Node**), после чего инбаунды создаются в мастере с указанием ноды.
Запускать `install_node.sh` на самой ноде в этом случае не нужно.

## Шаг 7. Запускаем бота

Сначала — Docker (один раз на сервере):

```bash
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version
```

Затем — бот:

```bash
cd /root/kometa
mkdir -p data
docker compose up -d
```

Первая сборка занимает 1–3 минуты. Проверяем:

```bash
docker compose ps                 # bot должен быть Up (healthy) через ~40 секунд
docker compose logs -f bot        # логи; выйти — Ctrl+C
```

В логах должно быть что-то вроде:

```
kometa | Запуск бота, планировщика и веб-слоя...
kometa | Веб-слой подписки: http://0.0.0.0:8080
```

Проверка веб-слоя:

```bash
curl -s http://127.0.0.1:8080/health      # ожидаем {"status":"ok"}
```

Остановить / перезапустить / обновить:

```bash
docker compose stop            # остановить
docker compose start           # запустить
docker compose restart bot     # перезапустить бота
docker compose down            # удалить контейнеры (данные в ./data остаются)
```

## Шаг 8. Проверяем, что всё работает

1. **Бот отвечает.** Открой своего бота в Telegram → `/start`. Должно появиться меню
   с кнопками «Попробовать бесплатно», «Тарифы», «Моя подписка», «Помощь».
2. **Админка.** Отправь `/admin` — если `ADMIN_IDS` заполнен верно, увидишь админ-меню.
   `/id` покажет твой ID (сверь с `ADMIN_IDS`).
3. **Пробный доступ.** Нажми «Попробовать бесплатно» — бот создаст пользователя в панели
   и выдаст ссылку-подписку. В панели 3x-ui появится клиент с этим email.
4. **Ссылка-подписка.** Открой выданную ссылку в браузере на телефоне/компьютере —
   должен скачаться текстовый файл (или показаться base64-строка) с `vless://…`.
5. **Подключение.** Импортируй ссылку в клиент:
   * Android — **v2rayNG** или **Hiddify**;
   * iOS — **Happ**, **Streisand**, **sing-box**;
   * Windows/macOS — **Hiddify**, **v2rayN**, **sing-box**.
   Включи соединение и проверь, например, `https://ifconfig.me` — должен показать IP сервера.
6. **Общий healthcheck** (этот скрипт умеет и уведомлять в Telegram):

   ```bash
   cd /root/kometa
   bash scripts/healthcheck.sh              # 0 — всё ок, 1 — есть проблема
   bash scripts/healthcheck.sh --notify     # + сообщение админу при проблеме
   ```

   Автозапуск каждые 15 минут:

   ```bash
   crontab -e
   # добавь строку:
   */15 * * * * cd /root/kometa && bash scripts/healthcheck.sh --notify --quiet
   ```

   Если пользуешься Uptime Kuma — добавь `--push "http://uptime:3001/api/push/XXXX?status=up"`.

## Локальный запуск без сервера (PANEL_TYPE=fake)

Нужен, чтобы проверить логику бота, не имея VPN-сервера: панель подменяется заглушкой,
«клиенты» живут в памяти, ссылки-подписки выдают тестовые конфиги.

## Обновление, бэкап, восстановление, откат

### Обновление кода бота

```bash
cd /root/kometa
git pull                        # или rsync с компьютера
docker compose up -d --build    # пересобрать образ и поднять
docker compose logs -f bot
```

### Обновление панели 3x-ui

```bash
sudo bash scripts/install_panel.sh --reinstall     # или просто:
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

База и настройки в `/etc/x-ui` при обновлении сохраняются. **Перед обновлением сделай бэкап.**

### Бэкап

```bash
cd /root/kometa
bash scripts/backup.sh
```

Скрипт кладёт в `./backups` архив вида `kometa-backup-2026-10-05_043000.tar.gz`, внутри:

* `kometa.db` — база бота (SQLite) + `kometa-db.sql.gz` — текстовый дамп;
* `panel/x-ui.db` — база панели, её конфиги и сертификаты;
* `MANIFEST.txt` — что внутри, размеры и как восстанавливать.

Проверки: `PRAGMA integrity_check` для каждой SQLite-базы и `tar -tzf` для архива.
Хранение — 14 дней (меняется флагом `--keep-days`). Старые архивы удаляются сами.

Ежедневно в 04:30:

```bash
crontab -e
30 4 * * * cd /root/kometa && bash scripts/backup.sh >> logs/backup.log 2>&1
```

> Бэкап на том же сервере — это ещё не бэкап. Если в `.env` задать
> `BACKUP_RSYNC_TARGET=user@other-host:/backups/kometa/`, скрипт после архивации
> выгрузит копию туда (нужен `rsync` и настроенный SSH-ключ).

### Восстановление

```bash
cd /root/kometa
tar -tzf backups/kometa-backup-ДАТА.tar.gz          # посмотреть содержимое
mkdir -p /tmp/restore && tar -xzf backups/kometa-backup-ДАТА.tar.gz -C /tmp/restore
cd /tmp/restore/kometa-ДАТА

# 1) База бота
docker compose -f /root/kometa/docker-compose.yml stop bot
cp /root/kometa/data/kometa.db /root/kometa/data/kometa.db.before-restore   # страховка
cp kometa.db /root/kometa/data/kometa.db
docker compose -f /root/kometa/docker-compose.yml start bot

# 2) База панели (если восстанавливаешь и её)
systemctl stop x-ui
cp /etc/x-ui/x-ui.db /etc/x-ui/x-ui.db.before-restore
cp panel/x-ui.db /etc/x-ui/x-ui.db
systemctl start x-ui
```

Восстановление только из текстового дампа (если файл `kometa.db` потерян):

```bash
gunzip -c kometa-db.sql.gz | sqlite3 /root/kometa/data/kometa.db
```

## Типичные ошибки и что делать

### 1. «Бот не стартует»

```bash
cd /root/kometa
docker compose logs --tail 100 bot
```

| Что в логах | Причина и лечение |
|---|---|
| `Unauthorized` / `401` от Telegram | неверный `BOT_TOKEN` (скопирован не полностью или отозван). Выпусти новый у @BotFather и обнови `.env`, затем `docker compose up -d` |
| `ValidationError` / `field required` | в `.env` не хватает обязательной переменной — сверься с таблицей шага 6 |
| `unable to open database file` | каталог `./data` не создан или недоступен: `mkdir -p /root/kometa/data && chmod 755 /root/kometa/data` |
| `address already in use` | порт 8080 занят (например, другой бот): `ss -tlnp \| grep 8080`, поменяй `WEB_PORT` в `.env` и в `docker-compose.yml` |
| `no such file or directory: /app/.env` | ты запускаешь не через compose: `.env` должен передаваться как `env_file` (см. `docker-compose.yml`) |
| контейнер `Restarting` по кругу | смотри ту же команду `logs`; чаще всего это токен или синтаксис `.env` |

Проверить синтаксис конфигурации:

```bash
docker compose config >/dev/null && echo "compose OK"
```

### 2. «Панель недоступна» (бот пишет об ошибке API)

```bash
curl -s -H "Authorization: Bearer <PANEL_TOKEN>" "http://IP:54321/<path>/panel/api/inbounds/list" | head -c 300
```

| Что видишь | Причина и лечение |
|---|---|
| `401 Unauthorized` | токен неверный/отозван. Новый: `x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin`. Проверь, что скоуп `admin` |
| пустой ответ / `Connection refused` | служба панели не запущена (`systemctl status x-ui`), неверный порт или закрыт порт в firewall (`ufw status`) |
| HTML вместо JSON | в `PANEL_URL` не хватает **web base path** (секретного пути). Посмотри его: `/usr/local/x-ui/x-ui setting -show` |
| `success: false`, `msg: ...` | смотри текст сообщения: обычно это несуществующий инбаунд или неподдерживаемый протокол |
| бот в Docker не видит панель на `127.0.0.1` | внутри контейнера `127.0.0.1` — это сам контейнер. Укажи в `PANEL_URL` публичный IP сервера, либо запусти бота с `network_mode: host` |

### 3. «Ссылка-подписка не открывается»

```bash
curl -s http://127.0.0.1:8080/health                 # внутри сервера — должно быть {"status":"ok"}
curl -sI http://IP_СЕРВЕРА:8080/health               # снаружи
ss -tlnp | grep 8080
ufw status | grep 8080
```

| Симптом | Причина и лечение |
|---|---|
| внутри работает, снаружи нет | порт 8080 закрыт в `ufw` (`ufw allow 8080/tcp`) **или в firewall хостера** (панель управления VPS → Security Group / Firewall) |
| `/health` отвечает, а `/sub/<token>` — 404 | токен подписки неверный/устаревший: возьми актуальную ссылку в боте («Моя подписка» → «Ссылка-подписка») |
| в боте ссылка вида `http://127.0.0.1:8080/...` | в `.env` не поправлен `PUBLIC_BASE_URL` — впиши `http://IP_СЕРВЕРА:8080` и перезапусти бота |
| клиент пишет «подписка пустая» | в `PANEL_INBOUND_IDS` указаны несуществующие ID или у клиента нет ни одного инбаунда — сверь ID в панели |
| ссылка открывается, но VPN не подключается | проблема не в подписке, а в инбаунде: смотри пункт 4 |

### 4. «Порт закрыт» / VPN не подключается

```bash
ss -tulpn | grep -E ':(443|51820)\b'      # слушает ли сервер
ufw status numbered                       # правила firewall
nc -vz IP_СЕРВЕРА 443                     # проверка снаружи (со своего компьютера)
```

* Нет строки `:443` — xray не перезапустился: `systemctl restart x-ui`,
  затем `journalctl -u x-ui -n 50 --no-pager`.
* Локально `nc` открывается, снаружи нет — почти всегда **firewall хостера** (Security Group)
  или `ufw`.
* UDP-порт AmneziaWG «не проверяется» через `nc` (UDP не отвечает на пустой пакет) —
  ориентируйся на `ss -ulpn` и на панель: AmneziaWG поднимает интерфейс, когда есть
  хотя бы один включённый клиент.
* Reality: если клиент подключается, но интернета нет — проверь, что домен маскировки
  не заблокирован у клиента, и что системное время на телефоне точное.
  Перебери домен: `sudo bash scripts/install_node.sh --sni www.samsung.com` (создаст
  второй инбаунд на другом порту — добавь его ID в `PANEL_INBOUND_IDS`).
* Провайдер режет 443/tcp — сделай резервный Reality-инбаунд на порту 8443
  (`--reality-port 8443`) и открой порт: `ufw allow 8443/tcp`.

### 5. «AmneziaWG не создаётся»

Скрипт скажет: «Панель X не умеет AmneziaWG (нужно 3.7.0+)». Обнови панель:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

Отдельно ставить `amneziawg-go` или `awg-quick` **не нужно и вредно**: в 3x-ui 3.7+
AmneziaWG встроен (userspace, без kernel-модуля), а старый путь через DKMS/awg-quick удалён.

### 6. «Диск переполнен»

```bash
df -h
du -sh /root/kometa/backups /var/lib/docker
bash scripts/backup.sh --keep-days 7      # уменьшить срок хранения
docker system prune -a                     # удалить неиспользуемые образы
```

## Безопасность

**Ключи вместо паролей.**
* SSH: вход только по ключу (`PasswordAuthentication no`), `PermitRootLogin prohibit-password`.
  Ключ — `ed25519`, приватную часть не копируй на сервер.
* Панель: длинный уникальный пароль (его сгенерировал `install_panel.sh`) + нестандартный
  порт + секретный `web base path`. Включи двухфакторную аутентификацию в настройках панели.
* API: только токен, никаких логина/пароля в `.env` (поля `PANEL_USERNAME`/`PANEL_PASSWORD`
  оставь пустыми).
* Бот: `ADMIN_IDS` — только твои ID. Токен бота = полный доступ к боту, не показывай его.

**Закрываем панель от посторонних.** Панель — это админка VPN: её видит только владелец.

Вариант 1 (простой, работает с ботом в Docker): оставить порт открытым, но полагаться на
пароль, fail2ban (включается установщиком) и секретный путь. Минимум — проверь, что
порт панели открыт **только** для нужных адресов.

Вариант 2 (жёсткий): панель слушает только localhost, вход — через SSH-туннель.

```bash
/usr/local/x-ui/x-ui setting -listenIP 127.0.0.1
ufw delete allow 54321/tcp
systemctl restart x-ui
```

С **твоего компьютера**:

```bash
ssh -L 54321:127.0.0.1:54321 root@IP_СЕРВЕРА
# затем в браузере: http://127.0.0.1:54321/<web_base_path>
```

> ⚠️ Если бот работает в Docker на том же сервере, после закрытия порта ему нужен доступ
> к панели. Тогда либо дай доступ только докер-сети:
> `ufw allow from 172.17.0.0/16 to any port 54321 proto tcp`
> (проверь подсеть: `docker network inspect bridge | grep Subnet`),
> либо оставь вариант 1.

**Ротация токенов.** Меняй токен, если он засветился (скриншот, переписка, чужой доступ
к серверу) — иначе бот не сможет управлять панелью:

```bash
# 1. Новый токен панели
/usr/local/x-ui/x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin
# 2. Вписать в .env → PANEL_TOKEN
nano /root/kometa/.env
# 3. Перезапустить бота
cd /root/kometa && docker compose up -d
# 4. Токен бота (если утёк его токен)
#    @BotFather → /revoke → выбрать бота → новый токен → в .env → docker compose up -d
```

**Файлы и секреты.**
* `.env` — `chmod 600`, в git не коммитится (`.gitignore`).
* Каталог `backups/` — `700`, архивы `600` (скрипт ставит права сам), но помни: в архиве
  лежат токены и база панели.
* `data/kometa.db` — персональные данные (Telegram ID), тоже не для чужих глаз.
* Не публикуй в канале скриншоты панели, `.env` и логи с токенами.

**Обновления.** Раз в неделю: `apt-get update && apt-get upgrade -y`,
`docker compose up -d --build`, обновление панели (шаг «Обновление»).
Перед каждым обновлением — `bash scripts/backup.sh`.

**Юридическое** (из ТЗ, раздел 2.3): не используй в рекламе слова «обход блокировок» —
это штраф 50–80 тыс. ₽ для гражданина. Формулировки: «защищённое подключение»,
«стабильный доступ к сервисам».

## Шпаргалка команд

```bash
# --- бот ---
cd /root/kometa
docker compose up -d                      # запустить
docker compose logs -f bot                # логи
docker compose restart bot                # перезапустить
docker compose up -d --build              # обновить код
docker compose down                       # остановить и удалить контейнеры

# --- проверки ---
bash scripts/healthcheck.sh               # здоровье: панель, бот, диск
curl -s http://127.0.0.1:8080/health      # веб-слой подписки
ss -tulpn | grep -E ':(443|51820)\b'      # порты VPN
ufw status numbered                       # firewall

# --- панель 3x-ui ---
x-ui                                      # интерактивное меню панели
systemctl status x-ui                     # состояние службы
journalctl -u x-ui -n 50 --no-pager       # логи панели
/usr/local/x-ui/x-ui setting -show        # текущие настройки (порт, путь)
/usr/local/x-ui/x-ui setting -getApiToken -tokenName kometa-bot -tokenScope admin

# --- обслуживание ---
bash scripts/backup.sh                    # бэкап
bash scripts/install_panel.sh --reinstall # обновить панель
sudo bash scripts/install_node.sh         # добить/проверить инбаунды
```
