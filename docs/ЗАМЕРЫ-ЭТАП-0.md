# Замеры «этап 0»: что именно делать руками

> **Дата:** 07.10.2026. **Зачем:** от замеров зависит всё остальное — какой канал поднимать,
> какой адрес покупать и стоит ли вообще. Полчаса замеров экономят 2 000 ₽ и вечер на покупку
> сервера, который не пройдёт.
>
> **Инструмент:** [scripts/lte_probe.sh](../scripts/lte_probe.sh) — только измеряет, ничего не меняет
> ни на сервере, ни на телефоне. Результаты копятся в CSV флагом `--report`.

---

## 1. Какой вопрос решает каждый замер

| Замер | Вопрос | Что делаем по ответу |
|---|---|---|
| 1. Режим включён? | проходит ли вообще что-то, кроме разрешённых сайтов | если всё проходит — аварийный уровень не нужен, живём на обычных нодах |
| 2. Что режется | TCP-порты, TLS по SNI, пустой SNI, QUIC, UDP | выбираем транспорт: Reality, TLS со своим доменом, WS+XHTTP за CDN |
| 3. Есть ли проходимая подсеть | `rc` пустых адресов в чужих `/24` | ищем входной адрес, только он даёт «вход в разрешённой подсети» |

## 2. Что подготовить (один раз)

* **Телефон с симкой** каждого оператора, который вас интересует: МТС, МегаФон, Билайн, Т2 (и Yota —
  у неё список может отличаться от материнского МегаФона).
* **Termux** (F-Droid или GitHub-релиз; версия из Google Play устарела) и пакеты:
  `pkg install curl openssl-tool python netcat-openbsd coreutils`
* **Файл скрипта на телефоне.** Проще всего: отправить `scripts/lte_probe.sh` себе в «Избранное»
  Telegram, затем `termux-setup-storage` и скопировать из `~/storage/downloads`. Альтернатива —
  ноутбук, подключённый к мобильной точке доступа этого же телефона (тот же оператор и та же симка,
  но проверка идёт с чужого стека — для грубых выводов годится, для точных лучше телефон).
* **Wi-Fi и VPN выключены.** Иначе меряете не то: запросы уйдут мимо мобильной сети.

## 3. Протокол: три шага, по возрастанию точности

### Шаг 1 — «включён ли режим» (~5 минут на оператора)

```bash
# Отчёт будет копиться в probes.csv, метка — ваш оператор и город
./lte_probe.sh --host 1.1.1.1 --ports 80,443,22 \
  --report probes.csv --label "МТС Новосибирск"
```

Читаем результат:

* «1. Контроль (интернет)» ❌ — сеть мертва или контрольный адрес недоступен: повторяем позже;
* все порты ✅, TLS ✅ — режима нет (или он мягкий): обычные ноды работают, аварийный уровень не срочен;
* порты ❌ по всем адресам, контроль ✅ — **режим включён**, идём дальше;
* TCP ✅, TLS ❌ — фильтр по SNI: спасёт маскировка (`--sni`) или свой домен.

### Шаг 2 — «что проходит у этого оператора» (~10 минут на оператора)

```bash
# Разрешённый сайт: если он проходит, а 1.1.1.1 нет — это и есть режим по адресам
./lte_probe.sh --host ya.ru --sni ya.ru --ports 443 --report probes.csv --label "МТС Новосибирск"

# Своя нода (если есть): понять, режет ли оператор именно её адрес
./lte_probe.sh --host <IP ноды> --sni <домен маскировки> --udp-port 443 \
  --report probes.csv --label "МТС Новосибирск"
```

Что смотреть: пункт 4 (TLS **без** SNI) — если он проходит, когда пункт 3 падает, рабочий путь —
TLS-инбаунд на IP-сертификате. Пункт 5 (QUIC) ❌ — Hysteria2/TUIC не вариант, ставка на TCP.

### Шаг 3 — «есть ли проходимая подсеть» (вечер, самое ценное)

```bash
# Список кандидатов: 22 хоста из docs/БЕЛЫЕ-СПИСКИ-ВНЕДРЕНИЕ.md §3.1.1 — по одному CIDR в строке
./lte_probe.sh --range-list candidates.txt --repeat 3 \
  --report probes.csv --label "МТС Новосибирск"
```

По каждому адресу в отчёте будет вердикт: `ПРОХОДИТ` (тишина = L3 пропускает), `БЛОК` (RST),
`КТО-ТО ЕСТЬ` (адрес занят — для проверки подсети нужен пустой), `СМЕШАННО` (повторить).

### Шаг 4 — подтверждение перед покупкой (после аренды IP за 0,26 ₽/час)

```bash
./lte_probe.sh --deep --host <арендованный IP> --deep-ports 443 --repeat 3 \
  --report probes.csv --label "МТС Новосибирск"
```

`--deep` различает RST и тишину — это и есть решение «брать адрес или нет».

## 4. Как читать `rc` (шпаргалка)

| rc | Что это | Вывод |
|---|---|---|
| 0, 60, 92 | TLS состоялся (60 — сертификат, 92 — HTTP/2) | адрес проходит |
| 52 | TLS состоялся, но сервер закрыл соединение без ответа (проверено на 95.181.181.5: handshake TLSv1.3 прошёл) | адрес проходит |
| 35 | обрыв на рукопожатии | **неоднозначно**: и перехват, и блок без RST, и кривой слушатель. В «прошло» не считать |
| 7 | RST | фильтр отбросил адрес. На **пустом** адресе это ТСПУ; на занятом RST может дать сам сервер |
| 28 | тишина | L3 пропускает (нет слушателя) **или** блок без RST — уточняется только `--deep` с повторами |

## 5. Дисциплина замера (иначе данные мусорные)

1. Только мобильная сеть: Wi-Fi и VPN выключены.
2. Контрольный адрес в начале **и** в конце прогона — режим переключается по вышкам прямо во время замера.
3. Не меньше трёх попыток на адрес (`--repeat 3`).
4. Минимум три оператора; для географии — 10 городов × 4 оператора (80 замеров, 2–3 вечера).
5. Фиксировать район/вышку, а не только город: у соседней вышки список может быть другим.
6. Замер годен ~7 дней. Сводная карты «оператор × регион» на сентябрь–октябрь 2026 не существует —
   её и собираем.

## 6. Что делать с результатами

1. Прислать `probes.csv` (или таблицу из него) — свожу в матрицу «оператор × город → что проходит»
   и отмечаю, какие каналы имеют смысл.
2. Выбрать 2–3 кандидата-подсети и проверить адреса (шаг 4).
3. Купить VPS **только** если адрес проходит на 2 из 3 операторов; аккаунт — не основной.
4. Поднять каскад (`scripts/add_cascade_exit.sh`), поставить ноде канал «резервная» в админке,
   проверить `/emergency` в боте.

## 7. Формат отчёта

`probes.csv` — обычный CSV с заголовком, дописывается при каждом запуске:

```
время,метка,оператор,регион,режим,цель,группа,вердикт,детали
2026-10-07 18:20,МТС Новосибирск,MTS,NSK,deep,203.0.113.7:443,,БЛОК,tls=0;hs=0;rst=3;to=0;other=0;sni=нет
2026-10-07 18:22,МТС Новосибирск,MTS,NSK,range,91.240.86.1,91.240.86.0/24,ПРОХОДИТ,rst=0;to=3;tls=0;hs=0
```

Оператор и регион берутся из переменных `LTE_OPERATOR` и `LTE_REGION`, метка — из `--label`.
