# День 0: мост, клиенты, приёмка

Здесь всё, что нужно, чтобы поднять «мост» (RU-адрес → зарубежный выход),
раздать три ссылки и закрыть приёмку Дня 0.

| Файл | Зачем |
|---|---|
| `30-deploy-bridge.sh` | ставит мост целиком: ядро v26.9.30, IPv6 off, ключи Reality, конфиг, служба, ссылки, реестр |
| `users.csv` | реестр выдачи: имя, UUID, дата выдачи, платформа, оператор, статус |
| `users.csv.example` | пустой шаблон реестра (одна шапка) — формат колонок |

Панели здесь нет намеренно: на трёх клиентах она только добавляет сущностей,
которые могут «не подняться». Конфиг — обычный `/usr/local/etc/xray/config.json`,
служба — `xray`.

## Шаг 6. Развернуть мост

```bash
scp -i secrets/id_dsh ops/30-deploy-bridge.sh root@<BRIDGE_IP>:/root/
ssh -i secrets/id_dsh root@<BRIDGE_IP> 'bash /root/30-deploy-bridge.sh \
  --exit-address <EXIT_ADDRESS> --exit-port <EXIT_PORT> \
  --exit-uuid <EXIT_UUID> --exit-pubkey <EXIT_PUBKEY> \
  --exit-sni <EXIT_SNI> --exit-shortid <EXIT_SHORTID> \
  --client-uuid <UUID_1> --client-uuid <UUID_2> --client-uuid <UUID_3>'
```

Первым делом — предпросмотр. Он **ничего не пишет и не ходит в сеть**, поэтому
его безопасно запускать даже на боевом узле:

```bash
bash /root/30-deploy-bridge.sh --dry-run --exit-address ... --client-uuid ...
```

Что обязано быть в выводе боевого запуска (это и есть приёмка шага 6):

- `Версия ядра: v26.9.30` — версия ядра закреплена; другая — ошибка (обходится
  `--allow-other-version`, но обходить не надо);
- `Пользователей: 3` и **три** строки `vless://…` — по одной на человека;
- `Служба xray: active` — то же, что `systemctl is-active xray` → `active`;
- строка реестра на каждого: `имя,uuid,дата_выдачи,платформа,оператор`.

Полезно сразу заполнить реестр (имя, платформа, оператор) — тогда его не придётся
править руками:

```bash
... --client "<UUID_1>,Иван,Android/Happ,МТС" \
    --client "<UUID_2>,Пётр,iOS/Streisand,Билайн" \
    --client "<UUID_3>,Аня,macOS/v2rayN,МегаФон"
```

Скрипт идемпотентен: повторный запуск **не перевыпускает ключи** и, если конфиг
не изменился, даже не перезапускает службу. Если у моста нет доступа к GitHub,
ядро ставится из локального архива: `--xray-zip /root/xray.zip`
(`Xray-linux-64.zip` скачивается на своей машине и копируется на мост).

Чего скрипт не делает: не трогает выходную ноду, не ходит в панель, не отправляет
никуда ни одного запроса «наружу» и не публикует адрес и ссылки.

### Отзыв ключа (второй UUID — не трогая остальных)

Убрать UUID из `--client-uuid` и запустить ту же команду снова:

```bash
ssh -i secrets/id_dsh root@<BRIDGE_IP> 'bash /root/30-deploy-bridge.sh \
  --exit-address ... --client-uuid <UUID_1> --client-uuid <UUID_3>'
```

Конфиг изменится → `xray` перезапустится → ссылка отозванного перестанет
работать, остальные не шелохнутся. В реестре он станет `отозван` с датой отзыва.
Перепечатать ссылки, ничего не меняя: `bash /root/30-deploy-bridge.sh --links-only`.

### Реестр

```bash
scp -i secrets/id_dsh root@<BRIDGE_IP>:/root/users.csv ops/users.csv   # забрать на свою машину
```

Формат: `имя,uuid,дата_выдачи,платформа,оператор,статус,дата_отзыва`.
`статус` и `дата_отзыва` скрипт ведёт сам, дату выдачи при повторных запусках
не переписывает. Файл лежит на мосте с правами `0600` — это персональные данные
клиентов, в репозиторий он не попадает (`.gitignore`).

Особенности, которые легко не заметить:

- поля разделены запятыми, поэтому запятых внутри имени/платформы быть не может
  (скрипт откажется работать, а не сдвинет колонки): пишите «Иван;Пётр», если
  очень нужно;
- имена, начинающиеся с `=`, `+`, `-`, `@`, при записи обезвреживаются (`'=1+1`),
  чтобы открытие реестра в Excel не выполняло формулу;
- повторный UUID — это **один** клиент: скрипт скажет об этом прямо. Одна ссылка
  на всех запрещена, у каждого свой UUID (иначе один отзыв рвёт всех, и нельзя
  понять, кто именно утёк).

## Шаг 7. Клиенты (15 мин)

| Платформа | Клиент |
|---|---|
| Android | Happ (или INCY ≥ 2.7.11) |
| iOS | Streisand или Happ |
| macOS | v2rayN или Throne, **TUN включить** |

На каждом устройстве:

1. импортировать **свою** ссылку, подключиться;
2. открыть <https://www.cloudflare.com/cdn-cgi/trace> → в строке `ip=` должен быть
   `EXIT_ADDRESS`, а не реальный адрес.

`api.ipify.org` и `ifconfig.me` намеренно заблокированы на сервере — для проверки
используйте именно `cdn-cgi/trace`.

Настройки клиента, без которых «работает, но не так»: домен/SNI — как в ссылке,
отпечаток `firefox` (в ссылке уже он), DNS — **через туннель** (иначе резолв уйдёт
оператору и проверка из шага 8 покажет утечку), для macOS — TUN.

## Шаг 8. Проверка утечек и приёмка (10 мин)

| # | Проверка | Команда / как смотреть | Ожидаемо |
|---|---|---|---|
| 1 | Резолв уходит в туннель | на мосте: `tcpdump -ni any port 53` (серфить на телефоне) | запросов к локальному DNS нет |
| 2 | IPv6 выключен | `ssh root@<BRIDGE_IP> 'ip -6 addr show scope global'` | пусто |
| 3 | Выход не отвечает посторонним | с любого другого хоста: `nc -zv <EXIT_IP> 443` | не подключается |
| 4 | Скорость | на телефоне | ≥ 5 Мбит/с |
| 5 | Устойчивость | держать подключение | ≥ 10 минут без обрывов |
| 6 | Все подключены | три человека, каждый со своей ссылкой | три разных UUID в панели/реестре |

Пункт 3 делается **на выходной ноде**, мост тут ни при чём. Скрипт печатает
готовые команды; коротко:

```bash
# на выходной ноде: разрешить только мосту, остальным — отказать
ufw allow from <BRIDGE_IP> to any port <EXIT_PORT> proto tcp
ufw deny <EXIT_PORT>/tcp
```

День 0 принят, если отмечены все пункты.

Честная оговорка про пункт 1. По умолчанию мост **не резолвит ничего сам**: весь
трафик (включая DNS-запросы клиентов) уходит на выход, и порт 53 на мосте молчит.
Если включить `--direct-ru` (РФ-трафик напрямую с моста — это нужно, когда через
мост пойдёт боевая нагрузка, чтобы не «выжигать» подсеть на разрешённых
РФ-сервисах), то РФ-домены будет резолвить сам мост, и на порту 53 появится его
собственный трафик. Это не утечка клиента, но приёмку по пункту 1 тогда следует
читать внимательно: смотреть, что запросы идут от ядра моста к системному
резолверу, а не от клиентов «мимо туннеля».

## Шаг 9. Если достижимый IP не найден

Обхода сегодня не будет — это следствие решения «только свой сервер».

Зафиксировать: сколько было смен IP, какие адреса, что именно показывал телефон
(скриншот или точный текст ошибки и время).

- **День 1:** метод «плавающий IP на час» (0,26 ₽/час) + Beget / VDSina / FirstVDS.
- **Пересмотреть схему B** (туннель внутри VK Звонков / Telemost / WB Stream) —
  это единственный путь, не зависящий от белого IP.

## Чего НЕ делать

- ❌ не отправлять `ops/00-timeweb-ticket.md` — письменная просьба о
  привилегированном размещении и след о цели аренды. Этого файла здесь нет и
  создавать его не нужно;
- ❌ не покупать «белый IP» у перекупов;
- ❌ не приоритизировать хостеров по community-датасету;
- ❌ не выдавать одну ссылку на всех (скрипт это запрещает и объясняет);
- ❌ не публиковать IP и ссылки;
- ❌ не ставить `fp=chrome`/`safari`/`ios` — в июньском режиме они помечены
  (скрипт по умолчанию ставит `firefox` и предупреждает, если попросить chrome);
- ❌ не обращаться в поддержку хостера с описанием задачи.

## Если что-то не работает — что прислать

Вывод самого скрипта целиком (не пересказ), плюс:

```bash
ssh root@<IP> 'systemctl status xray --no-pager -l; journalctl -u xray -n 50 --no-pager'
ssh root@<IP> 'cat /usr/local/etc/xray/config.json'   # UUID можно заменить на xxx
```

Что именно видно на телефоне: скриншот или точный текст ошибки и время.
И результат шага 1 (включён ли режим прямо сейчас).

## Ограничения скрипта (чтобы не было сюрпризов)

- Мост — только IPv4. IPv6 выключается намеренно (приёмка, пункт 2), поэтому
  `--exit-address` — IP-адрес, а не имя: имя заставило бы мост резолвить его
  самому. Домен разрешается отдельным флагом `--allow-exit-hostname`, но это
  осознанное «пусть на мосте будет DNS».
- `MSS-clamp` (по умолчанию MTU 1280 → MSS 1240) ставится в `FORWARD` и лечит
  классическое «SSH работает, а сайты висят» на мобильных сетях.
- `--harden-firewall` включает `ufw` с двумя разрешёнными портами (SSH и мост).
  По умолчанию фаервол не трогается: скрипт только добавляет правило для порта
  моста, если `ufw` уже включён.
- Выходную ноду скрипт не настраивает: её ключи Reality берутся из `--exit-*`
  (их печатает `scripts/install_node.sh` выходной ноды или панель выхода).
