# Батч 2 — ДИСКРИМИНАТОР: фильтр по адресу назначения или что-то ещё?
#
# Вопрос, на который отвечает этот батч.
# Замер 14:02 показал: адреса в плотных белых /24 ПРОХОДЯТ (rc=0, TLS состоялся),
# а наша зарубежная нода (живой TLS-слушатель, вне списка) молчит (rc=28).
# Но тишина на конкретном хосте может объясняться не фильтром, а проблемой
# самого хоста. Нужен контроль, который отличается от нод ТОЛЬКО признаком
# «в белом списке / не в белом списке».
#
# Такой контроль — 72.56.38.62 (TimeWeb, AS9123, РОССИЙСКИЙ адрес). Он:
#   * НЕ входит ни в CIDR-базу, ни в rewl (проверено whitelist_check.sh);
#   * отвечает TLS на 443 с обычного канала (проверено, rc=0) — то есть хост живой.
# Если РОССИЙСКИЙ адрес вне списка тоже молчит, а адреса В списке проходят —
# фильтр работает по признаку «в списке», а не по географии.
#
# Формат строки: <метка> <адрес>. # — комментарий.
#
# Ожидания под включённым режимом:
#   wl-*      → ПРОХОДИТ (rc=0/52) либо тишина, но БЕЗ RST
#   NOT-wl-*  → БЛОК: rc=7 (RST) либо rc=28 (тишина)
