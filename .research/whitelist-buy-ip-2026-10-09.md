## 0. Короткий ответ

**Рынка «покупки белого IP» не существует. Никто публично не продаёт вход в белые списки.** Проверено:

- **Ни один хостер не заявляет выдачу «белых» адресов.** Проверено 8 страниц хостеров (07.10.2026, `[ИЗ КОРПУСА]`) — 0 вхождений «белый список» / «белых списк» / «ТСПУ» / «РКН». Сегодня добавлены `4vps.su`, `vdsina.ru`, `beget.com`, `ruvds.com`, `firstvds.ru` — то же самое `[ПРОВЕРЕНО 09.10.2026]`.
- **Нет ни одного предложения «аренда белого IP» / «продам белый IP» / «IP из белых списков купить»** — ни на NTC, ни на searchengines.guru, ни в выдаче поисковиков. `[НЕ НАЙДЕНО]`
- **Ключевая причина — рынок не «не сложился», а административно закрыт.** В **январе 2026** Роскомнадзор ограничил работу VPN-сервисов, арендовавших серверы с IP из белого списка, — **облачным провайдерам запретили сдавать такие адреса в аренду** `[ПРОВЕРЕНО 09.10.2026, anti-malware.ru 31.08.2026, пересказ РБК]`. А **31.08.2026** Минцифры попросило хостеров/CDN **выделить IP разрешённых сайтов в отдельные подсети**, куда «посторонним организациям использовать адреса не позволят» `[ПРОВЕРЕНО 09.10.2026, там же]`. То есть «эффект соседа», на котором держится вся схема, целенаправленно демонтируется (см. §4.3).
- **Публичное предложение — только обходные пути, а не «покупка входа»:** аренда VPS в РФ с последующим **перебором (reroll) IP** (§1), аренда целой `/24` у RIPE-брокера (§2), либо готовые VPN-ключи «с белыми списками» от перекупов (§3).
- **Самый дешёвый и единственный документированный автоматизированный путь — Selectel + открытый инструмент `selectel_roller`** (§1.2). **Самый дешёвый вход «в лоб» — 4VPS** (5 бесплатных смен IP со сменой подсети).

> **Честный вывод:** купить «белый IP» как товар нельзя. Можно купить **VPS в РФ и лотерейный билет** — право пересоздавать адрес, пока не попадёшь в разрешённую `/24`. Вероятность, число попыток и срок жизни результата ни один продавец не гарантирует.

## 1. Российские облака: где «белый IP» выбивается перебором

### 1.0. Механика, подтверждённая полем

- **Способ ровно один — перебор.** NTC 24230, пост 2, `akloman`, 16.04.2026: «И не нароете никогда, это непубличная информация… **Тут способ один — перебор ip. Заказываете VPS+IP, проверяете специальными скриптами работу при БС, повторять до успеха**» `[ПРОВЕРЕНО 09.10.2026, NTC /t/24230]`.
- **Гранулярность действительно `/24`, но плотность низкая.** Скан Habr/twl (25.04.2026, 302K охвата): агрегация по `/24` дала **максимальную плотность 37,5 %** (`185.71.67.0/24`, Storm Networks); **подсетей с плотностью ≥50 % — ноль** `[ПРОВЕРЕНО 09.10.2026, habr.com/ru/articles/1027276]`. Практический вывод: попадание в «правильную» `/24` **не гарантирует**, что конкретный адрес оттуда пропустят.
- **У разных операторов фильтр разной глубины.** `ValdikSS`, NTC 24230, пост 16, 03.05.2026: «У **МТС и Теле2 только фильтр по L3** — если IP пингуется, то он доступен в полном объёме, любые порты и протоколы»; у **Мегафона дополнительно фильтр по SNI** `[ПРОВЕРЕНО 09.10.2026]`. Пост 18, `knitabsorbed`: в Москве в марте 2026 **Билайн фильтровал только по IP, не по SNI** `[ЗАЯВЛ]`.
- **Список у каждого оператора свой и меняется.** `[ИЗ КОРПУСА]` + подтверждено Habr-статьёй: «Списки постоянно меняются. Что-то добавляют, что-то убирают… **Одна подсеть в БС у Мегафона может не быть у МТС**» `[ПРОВЕРЕНО 09.10.2026]`.

### 1.2. `selectel_roller` — единственный публичный инструмент перебора `[ПРОВЕРЕНО 09.10.2026]`

- **Репозиторий:** `bymakk/selectel_roller` — создан **18.04.2026**, последний push **22.04.2026**, **68 ★**, 7 форков, не заархивирован, Python (GitHub API).
- **Что делает:** «Автоматический перебор floating IP на Selectel. Программа запрашивает IP-адреса в указанных регионах, сверяет их с `whitelist.txt` и оставляет только адреса из нужных сетей. **Остальные удаляет.**»
- **Пропускная способность:** на дашборде из README — «Время работы: 00:05:23 · **IP/мин: 28.4** · Всего IP: 142 · Удалено IP: 141». То есть **~1 700 адресов/час**.
- **Поддерживает 2 аккаунта параллельно**, регионы `ru-1`, `ru-2`, `ru-3`; есть фоновый reconciler, который удаляет «лишние» IP.
- **Формат `whitelist.txt`:** CIDR или одиночные IP, например `5.35.0.0/16`, `194.87.0.0/18`.
- **Авторизация:** OpenStack Keystone v3, логин/пароль/`account_id` Selectel.
- ⚠️ **Файл `whitelist.txt` — пользовательский.** Это **не** гарантия, что адрес реально проходит под БС: попадание в файл = «я так думаю». Живой тест с SIM обязателен.

### 1.3. Вердикт по перебору

1. **Реально только у Selectel** (открытый API + отсутствие правила «не отказываться от IP») и **формально у Baxet** (50 бесплатных смен, но без гарантии белых подсетей в пуле).
2. **Yandex Cloud и VK Cloud — не «перебор», а рулетка с баном.** У обоих документированы случаи отзыва IP и блокировки аккаунта именно за перебор `[ЗАЯВЛ, NTC 24230]`.
3. **У каждого оператора свой список** — успех на Мегафоне в Иваново не переносится на МТС в Москве `[ИЗ КОРПУСА + Habr]`.
4. **Срок жизни результата не гарантирован никем.** Замеры корпуса: 2 часа (CDN), ~4 суток (шаред-хостинг), **~3,5 месяца (ВМ в VK Cloud)** `[ИЗ КОРПУСА]`.

### 2.3. Почему аренда `/24` — не решение задачи

Аренда `/24` **не даёт** входа в БС, потому что:
1. Ключевое требование — адрес должен быть **в конкретном списке конкретного оператора**, а `/24` из пула брокера туда почти наверняка не входит.
2. Белые списки собраны из **уже работающих** ресурсов (сканированием); свежеарендованная `/24` не «станет белой» от факта аренды.
3. **Аренда чужой `/24` не создаёт «эффект соседа»** — фильтр смотрит на dst-IP, а не на владельца блока. Адрес либо в правиле, либо нет.
4. **Минцифры (31.08.2026)** прямо требует изолировать разрешённые IP в подсети, недоступные посторонним `[ПРОВЕРЕНО 09.10.2026]` — то есть сама конструкция «мой сервер в белой `/24`» демонтируется.

**Ценность аренды `/24` для этой задачи: низкая.** Она имеет смысл только как способ получить **свою AS + много адресов для массового перебора** — но перебор всё равно упирается в то, что БС у оператора конечен и уже занят.

1. **Административный запрет (главный).** Январь 2026: РКН **запретил облачным провайдерам сдавать в аренду IP из белых списков** `[ПРОВЕРЕНО 09.10.2026]`. Это прямо убивает легальный рынок.

## 7. Итоговая рекомендация

1. **Не искать «продавца белого IP» — его нет.** Любой, кто предложит «купить вход в белые списки» за деньги, с высокой вероятностью продаёт либо обычный VPS с наценкой, либо подписку (§3), либо мошенничество.
2. **Если задача — получить адрес в БС технически, самый дешёвый документированный путь:**
   - **Selectel** (VDS от **200 ₽/мес** + IP **182,28 ₽/мес**) + `selectel_roller` (бесплатно, open source) — **~28 IP/мин** через официальный API;
   - либо **4VPS** — **5 бесплатных смен IP с выбором подсети**, далее **100 ₽**; или **Baxet** — **50 бесплатных смен** (но без гарантии белых подсетей в пуле).
3. **Избегать Yandex Cloud и VK Cloud для перебора** — оба документированно банят за это (§1.1, §4.2).
4. **Аренда/покупка `/24` (5 000–19 999 ₽/мес или ≈$4 350–10 500) задачу НЕ решает** — это покупка адресов, которых нет в БС (§2.3).
5. **Учитывать, что окно закрывается:** запрет РКН (январь 2026) + изоляция подсетей Минцифры (31.08.2026). Горизонт планирования — месяцы, не годы.
6. **Альтернатива, не требующая белого IP вообще:** Yandex Cloud Functions (free tier бессрочно, `functions.yandexcloud.net` в БС у всех операторов) — §4.4.
