# Замер на втором операторе — инструкция для пересылки

> **Зачем.** Правила замера требуют минимум **два оператора**: один ничего не доказывает.
> Сейчас проверен только МТС. Эта инструкция рассчитана на человека, у которого **другой
> оператор** (МегаФон, Билайн, Т2, Yota) и **любой ноутбук**. Репозиторий ему не нужен —
> достаточно скопировать один блок в терминал.

## Что нужно от знакомого

1. **Ноутбук** (macOS или Linux; на Windows нужен WSL или Git Bash).
2. **Телефон с его SIM**, Wi-Fi на телефоне **выключен**, горит 4G/5G.
3. Ноутбук подключён к телефону: кабелем (надёжнее) или через «Точку доступа».
4. **VPN на ноутбуке выключен.** Через VPN «работает» всё, и замер становится фикцией.

## Команда (скопировать целиком в терминал)

```bash
echo "=== Контроль (должен быть rc=0) ==="
curl -s -o /dev/null -m 8 https://ya.ru; echo "ya.ru rc=$?"
echo "=== Адреса В белом списке (ожидание: проходят) ==="
for ip in 91.215.42.5 176.57.66.5 91.215.43.5 195.208.66.5; do
  curl -sk -o /dev/null -m 8 "https://$ip/"; echo "$ip rc=$?"
done
echo "=== Адреса ВНЕ списка (ожидание: молчат, если режим включён) ==="
for ip in 1.1.1.1 146.255.188.12 77.221.147.230 72.56.38.62; do
  curl -sk -o /dev/null -m 8 "https://$ip/"; echo "$ip rc=$?"
done
echo "=== Контроль в конце ==="
curl -s -o /dev/null -m 8 https://ya.ru; echo "ya.ru rc=$?"
echo "=== Выход (должен быть адрес телефона) ==="
ifconfig 2>/dev/null | grep -E 'inet (172\.20\.10|192\.168\.4[23])' || ip -4 addr | grep -E 'inet (172\.20\.10|192\.168\.4[23])'
```

Если `ifconfig`/`ip` ничего не показал — значит ноутбук **не** в сети телефона, и замер
недействителен: переподключите.

## Как читать (для того, кто пришлёт вывод)

| Что видно | Вывод |
|---|---|
| `ya.ru rc=0`, адреса **в** списке rc=0, адреса **вне** списка rc=7 или 28 | режим ограничений **включён** у этого оператора |
| всё rc=0 | режима нет (как на проверенной точке МТС) |
| `ya.ru` не отвечает | замер недействителен, повторить позже |
| rc=35 | неоднозначно: и блок без RST, и перехват — **не считать «прошло»** |

Расшифровка rc: `0/60/92` — TLS состоялся (проходит); `52` — TLS состоялся, но ответ пустой
(тоже проходит); `7` — RST от фильтра (блок); `28` — тишина (нет слушателя **или** блок).

## Что прислать назад

1. Вывод команды целиком (копипастой, не пересказом).
2. Оператор и город.
3. Строку из блока «Выход» — она подтверждает, что замер шёл через телефон.

## ⚠️ Важно при разборе: одиночный rc=28 ничего не доказывает

Проверено на живом замере 09.10.2026: адрес **в** белом списке `176.57.66.5` один раз дал
`rc=28`, хотя до этого проходил три раза из трёх. Причина — обычная нестабильность канала,
а не блокировка. Поэтому:

* **не делайте вывод по одному адресу** — смотрите на картину по группам
  (четыре «в списке» против четырёх «вне списка»);
* если картина смешанная — **повторите блок команд** ещё раз и пришлите оба вывода;
* признак настоящего режима — **устойчивое** молчание (rc=7 или rc=28) всех адресов
  вне списка при работающих адресах в списке, а не единичные таймауты.

## Чего делать НЕ надо

* Не мерить через VPN и не мерить с включённым Wi-Fi на телефоне.
* Не менять SNI, порт или протокол: фильтр работает по IP назначения, это не поможет.
* Ничего не покупать и не подключать платных сервисов под эту проверку.
