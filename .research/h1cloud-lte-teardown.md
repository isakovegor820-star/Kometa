## 0. Короткий ответ (10 строк)

1. «LTE-доступ» — **не LTE и не мобильная связь**. Это брендированное название второго VPN-инбаунда, трафик которого идёт через **CDN-шлюз российского облака** (Yandex/VK/Beeline/Selectel/Timeweb/Beget-класс), чьи узлы присутствуют в IP-белых списках мобильных операторов РФ.
2. Технически это схема **VLESS → XHTTP → TLS → CDN → TLS → nginx → Xray**, документированная независимо от H1Cloud; сам H1Cloud в UI пишет: «Создадим один инбаунд „Белые списки“ через наш CDN-шлюз. Адрес и SNI задаёт CDN из белых списков операторов» `[ПРОВЕРЕНО 2026-10-09]`.
3. Ключевое: белые списки мобильных операторов РФ — это **списки разрешённых IP-подсетей** (CIDR), а не SNI/домены. Подтверждено обсуждением на Habr QnA и публичным CIDR-файлом на 30 228 подсетей `[ПРОВЕРЕНО 2026-10-09]`.
4. **Экономика подтверждена из первоисточника** — публичного API `https://my.h1cloud.net/api/tariffs`: `"lte": {"base_price": 500, "price_per_gb": 2}` — ровно 500 ₽ + 2 ₽/ГБ, как в видео `[ПРОВЕРЕНО 2026-10-09]`.
5. Есть **второй, более дорогой тариф**, о котором в видео не сказано: `Premium LTE` = `"lte_price": 1500, "traffic_price_per_gb": 5.0, "traffic_max_gb": 10000` — 1500 ₽ подключение + 5 ₽/ГБ, потолок 10 000 ГБ/мес `[ПРОВЕРЕНО 2026-10-09]`.
6. Есть **третий вариант — «LTE Custom, персональный»**: **+5000 ₽ разово** сверх обычного подключения, «дальше, как обычный LTE (те же цены за ГБ)» — то есть 5500 ₽ на старте, зато личный домен вместо общего `[ПРОВЕРЕНО 2026-10-09]`.
7. Маржа: независимый источник оценивает **оптовую цену CDN-трафика в ~0,6 ₽/ГБ**. H1Cloud продаёт тот же ресурс по 2 ₽/ГБ — **наценка ≈3,3×** (у Premium — **≈8,3×**) `[ПРОВЕРЕНО 2026-10-09]`.
8. Оплата за LTE — это **не разовые 500 ₽, а подписка**: в UI поле называется `vpn_bs_monthly_price` («в мес.»), то есть 500 ₽ — это плата за подключение варианта, а дальше ежемесячно списывается стоимость пакета ГБ `[ПРОВЕРЕНО 2026-10-09]`.
9. **Юрлицо — не российское:** ОсОО «Классик Стайл», рег. номер 307589-3301-ООО, Бишкек, Кыргызская Республика. Оферта прямо заявляет, что H1Cloud не является российским юрлицом и **не сотрудничает с госорганами РФ** `[ПРОВЕРЕНО 2026-10-09]`.

Дословные фрагменты ответа:

## 2. ЧТО ЭТО ТЕХНИЧЕСКИ

### 2.1. ПОДТВЕРЖДЕНО

**(1) Это CDN-туннель, а не «белый IP-адрес» и не «свой LTE».**
Собственный текст интерфейса H1Cloud `[ПРОВЕРЕНО 2026-10-09]`:

> «Создадим **один инбаунд «Белые списки» через наш CDN-шлюз**. Адрес и SNI задаёт **CDN из белых списков операторов**, выбирать тут нечего. **Прямые Reality-подключения в этом режиме не создаются**.»

**(2) Транспорт — VLESS over XHTTP за CDN.** В примере ответа API `POST /api/v1/servers/{id}/clients` ссылка выглядит так:

```
vless://0c7ade4b-...@cdn.host:443?...&type=xhttp&...#vasya
```

`[ПРОВЕРЕНО 2026-10-09]` — домен в примере обезличен (`cdn.host`), реальный не раскрыт.

UI-конфигуратор сервера предлагает четыре транспорта `[ПРОВЕРЕНО 2026-10-09]`:
- `VLESS TCP Reality` — «Классика: TCP + Reality + XTLS Vision. Самый быстрый и совместимый вариант.»
- `VLESS gRPC Reality` — «gRPC поверх Reality: выглядит как HTTP/2-трафик, помогает там, где режут голый TCP.»
- `VLESS xHTTP Reality` — «xHTTP поверх Reality: HTTP-запросы, устойчивее к DPI, чуть медленнее.»
- LTE-конфиг (обход) — отдельный, выдаётся только с LTE-доступом.

Внутренние имена каналов инбаундов (из документации API): **`main`, `reality`, `bs`, `wscdn`** — `bs` = «белые списки», `wscdn` = WebSocket-CDN `[ПРОВЕРЕНО 2026-10-09]`.

**(3) Белые списки мобильных операторов РФ — это IP-подсети, а не SNI.** `[ПРОВЕРЕНО 2026-10-09]`
- Обсуждение на Habr QnA: *«при белых списках разрешены подключения только на определённые IP адреса. если твой впн сервак не входит в этот список (а 99% не входят), то нифига ты не подключишься»*; *«Чтобы у тебя заработали белые списки, у тебя должен быть начальный сервер подключения из масок БС… а потом уже веди за бугор»*.
- Публичный CIDR-файл `hxehex/russia-mobile-internet-whitelist/cidrwhitelist.txt` — **30 228 подсетей** в 90 разных первых октетах `[ПРОВЕРЕНО 2026-10-09]`.

Это объясняет, почему смена SNI/порта не помогает на «своём сервере» и почему работает CDN-схема: **IP-адреса узлов крупных российских CDN уже входят в списки.**

**(4) Механика схемы (независимое описание, полностью совпадает с продуктом H1Cloud)** `[ПРОВЕРЕНО 2026-10-09]`:

```
Клиент
  └── HTTPS-запрос к домену раздачи
        └── CDN сеть
              └── HTTPS к домену источника
                    └── nginx на VPS
                          └── локальный Xray-core
                                └── интернет
```
*VLESS → XHTTP → TLS → CDN → TLS → nginx → Xray.* Подходящие CDN названы прямо: **Yandex, VK, Beeline, Selectel, Timeweb, Beget**. Нужны **два домена** (домен раздачи у CDN + домен источника на VPS).

**(5) Продукт H1Cloud — это ровно (б) реверс-туннель через разрешённый ресурс, а именно CDN российского облака.** Соответствие признаков:

| Признак схемы из гайда | Реализация у H1Cloud | Источник |
|---|---|---|
| Домен раздачи (общий) | вариант **«LTE Общий»**: «Общий домен на всех клиентов» | UI ЛК |
| Домен раздачи (личный) | вариант **«LTE Custom»**: «Отдельный домен только для вас», «Поднимаем домен на сети раздачи» | UI ЛК |
| Домен источника + сертификат | «Создаём домен и сертификат», «Домен создаётся автоматически, обычно готов за 10–30 минут» | UI ЛК |
| Сайт-заглушка на 443 | «на каждый инбаунд, порт 443, наш сайт-заглушка. Снаружи это обычный HTTPS-сайт.» | UI ЛК |
| CDN-ресурс | вся ветка `/api/cdn/create`, `/api/cdn/activate`, `/api/cdn/state`, `/api/cdn/retry`, `/api/cdn/disable`, `/api/cdn/delete`; админ-панель `/cdn-admin` | бандл ЛК |
| nginx+Xray на ноде | свой инбаунд в 3x-ui / Remnawave-нода | API-доки, UI |

Ключевая деталь: документация API требует, чтобы **версия ядра Xray на сервере совпадала с версией ядра клиента Happ** («иначе туннель подключается, но трафик не идёт»), а список версий — `26.6.27 / 26.7.11 / 26.7.28`. Независимый гайд называет ровно тот же порог: «Xray новее **26.6.27**; Happ и INCY уже на **2.7.11**» `[ПРОВЕРЕНО 2026-10-09]`.

### 2.2. ОПРОВЕРГНУТО

- **(а) «Отдельный IP-адрес в белой подсети» (эффект соседа) — ОПРОВЕРГНУТО.** H1Cloud прямо пишет, что прямые подключения в этом режиме не создаются, а адрес и SNI задаёт CDN. Плюс независимый гайд: белые IP «сейчас получить реально только покупкой у перекупов за огромные деньги», и это признано устаревшим подходом.
- **(г) «Кастомный LTE = свой домен на своём сервере» — ОПРОВЕРГНУТО в пользу CDN-варианта.** Custom меняет только **домен раздачи** (личный вместо общего); трафик всё равно идёт через CDN-шлюз H1Cloud, а не напрямую на сервер клиента. Прямое подключение по-прежнему невозможно — режим «белых списков» работает только через CDN.

### 2.3. ЧЕГО НЕ УДАЛОСЬ УСТАНОВИТЬ

- **Конкретный CDN-провайдер и реальные домены раздачи** `[НЕ НАЙДЕНО]`. `/api/cdn/state` требует авторизации; в бандле реальные хосты не зашиты (приходят с сервера); `vlesshelp.h1cloud.net` **не резолвится** (NXDOMAIN, хотя NS домена — Cloudflare) `[ПРОВЕРЕНО 2026-10-09]`.
- **Технические детали инбаунда** (порт, путь, `xhttp extra`, SNI) — доступны только в авторизованном ЛК `[НЕ НАЙДЕНО]`.
- **(в) «Собственный шлюз H1Cloud с доменом и SNI-фронтом»** — формально это так и есть (`наш CDN-шлюз`), но H1Cloud **не владеет** CDN-инфраструктурой; он её арендует/агрегирует. Собственный у H1Cloud — только слой управления (генерация домена, сертификата, конфига) `[ГИПОТЕЗА, обоснованная]`.
- **Причастность DNS-туннелей или VK TURN** — признаков не найдено вовсе `[НЕ НАЙДЕНО]`.

### 3.5. Технические риски, вытекающие из архитектуры

1. **Общий домен = общая судьба.** Собственное предупреждение H1Cloud в UI: «**Риск блокировки выше: домен общий, при жалобах может пострадать вместе с другими**» `[ПРОВЕРЕНО 2026-10-09]`. Один абуз-жалобщик кладёт домен для всех клиентов варианта «Общий».
2. **CDN как единая точка отказа.** Если CDN-провайдер ужесточит правила, потребует прекратить передачу нестандартного трафика или исключит IP из белых списков — схема ломается целиком. H1Cloud в оферте (п. 8.5) заранее оговорил право менять домен «при прекращении работы партнёра».
3. **Жёсткая привязка версии ядра.** Клиент и сервер должны иметь совпадающую версию Xray (`26.6.27 / 26.7.11 / 26.7.28`); несовпадение = «туннель подключается, но трафик не идёт». Обновление приложения Happ в App Store/Google Play может **сломать доступ до обновления сервера** — и наоборот.
4. **Зависимость от вендора.** Конфиг, домен, сертификат, CDN-ресурс — всё на стороне H1Cloud. Уход/блокировка = полная потеря инфраструктуры без компенсации.
5. **Перевыпуск конфига необратим** и роняет сервер на 2–3 минуты; старые ссылки у всех клиентов перестают работать.
6. **Учёт трафика на шлюзе.** «Расход проверяется на шлюзе при открытии списка. Если шлюз не отвечает, статус и трафик отмечаются как недоступные» — при сбое шлюза **расход трафика не виден**, а значит возможны неприятные сюрпризы по списаниям `[ПРОВЕРЕНО 2026-10-09]`.

## 7. ГЛАВНЫЕ ВЫВОДЫ

1. **Продукт реален и цены в видео точны.** 500 ₽ + 2 ₽/ГБ — подтверждено из публичного API продавца. Но в видео умолчали о **Premium LTE (1500 ₽ + 5 ₽/ГБ)** и **LTE Custom (+5000 ₽ разово)**.
2. **«LTE» — маркетинговое имя, а не технология.** Никакого отношения к сотовой связи продукт не имеет: это CDN-туннель (XHTTP over VLESS) через узлы российского облака, чьи IP уже в белых списках операторов.
3. **Экономика — это перепродажа трафика с наценкой 3,3× (Premium: 8,3×)** к оптовой цене CDN. Реальная ценность — автоматизация сборки и ротации конфигов, а не гигабайты.
4. **Юридическая конструкция противоречива.** Оферта (пп. 9.3, 9.8) запрещает ровно то, что продукт делает и как он рекламируется; п. 9.7 даёт право блокировать без предупреждения. Для реселлера это означает нулевую правовую защиту.
5. **Хостер честно признаёт нестабильность:** 20 нод под блокировкой за сутки, анти-ТСПУ система готова на 90 %, восстанавливает ~60 % случаев. Это не «обход, который всегда работает».
6. **Бренду ~3 месяца** (домен зарегистрирован 2026-07-03), независимых отзывов и следов почти нет. Два домена документации (`vlesshelp.h1cloud.su`, `vlesshelp.h1cloud.net`) мертвы.
7. **Есть полноценное публичное REST API** с документацией — редкость для этого сегмента; позволяет строить собственного бота-реселлера. Но покупки и списания через API недоступны, а ключ видит только серверы владельца.
